# @tradinggoose/billing 0.2.0-dev.9

This is an intermediate correction candidate preserving the0.2 canonical string-money design. It is not operational build selection, full financial/native integration, independent review PASS, registry publication or production cutover authority. Immutable0.1.0-dev.2 must not be adopted: its binary64 money arithmetic fails exact admission. Financial policy and receipts use canonical decimal strings, with integer-string cents at the invoice boundary. Numeric monetary inputs and older float receipts are rejected; there is no compatibility or runtime backfill lane.

Studio owns the one maintained policy implementation. The tarball bundles canonical `packages/db/schema` source directly into ESM and generates declarations from that same source. It imports no ambient pool, environment credential or application service. Drizzle ORM0.44.7 is an exact peer; Postgres.js4.1.0 is an exact peer and supplies caller-owned transactions and its default lossless NUMERIC string parser. Do not install custom NUMERIC-to-Number parsing. The `@tradinggoose/db` workspace development dependency is build-only and is absent from the consumer runtime contract. BigNumber.js9.3.1 is pinned and bundled; private BigNumber objects never enter DTOs.

```ts
import postgres from 'postgres'
import { drizzle } from 'drizzle-orm/postgres-js'
import { createInvocation, admitModelStep, acceptModelStep, verifyAcceptance } from '@tradinggoose/billing'
import { addMoney, monetary } from '@tradinggoose/billing/money'

const sql = postgres(process.env.DISPOSABLE_DATABASE_URL!)
const db = drizzle(sql)
const binding = await db.transaction(tx => createInvocation(tx, {
  actorUserId: 'authenticated-actor', workspaceId: 'authorized-workspace',
  runId: 'server-assigned-native-run', operationKey: 'server-assigned-operation',
  purpose: 'copilot', quotedHoldUsd: '0.2', schedulerReady: true,
}))
await db.transaction(tx => admitModelStep(tx, binding, { stepNumber: 0, retryCount: 0 }, true))
// Delegate exactly one native model call, then await acceptance before effects/next contact.
await db.transaction(tx => acceptModelStep(tx, binding, { stepNumber: 0, retryCount: 0 }, {
  usage: { totalTokens: 42 },
}))
const accepted = await db.transaction(tx => verifyAcceptance(tx, binding, { stepNumber: 0, retryCount: 0 }))
// accepted.appliedUsd is a string; modelUsd remains 'unavailable'.
console.log(addMoney('0.1', '0.2')) // '0.3'
console.log(monetary('0.30000000000000001')) // exact original string
await sql.end()
```
