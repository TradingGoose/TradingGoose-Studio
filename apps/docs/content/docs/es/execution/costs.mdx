TradingGoose mide la ejecución de flujos de trabajo, el uso de modelos y el tiempo de ejecución de Function/herramientas personalizadas. Los cargos usan la configuración y el nivel efectivo del responsable de facturación del espacio de trabajo, sea usuario u organización.

## Cómo se calculan los costos

Cuando la facturación está habilitada, el uso puede incluir tres componentes de costo:

- **Cargo de ejecución**: el cargo de flujo de trabajo configurado multiplicado por el multiplicador de ejecución del nivel, según la cotización guardada para esa ejecución.
- **Uso de modelos de IA**: el costo del modelo del proveedor registrado por cada span de ejecución, multiplicado por el multiplicador de costo de modelos del nivel guardado en esa cotización.
- **Tiempo de ejecución de Function**: el cargo por segundo configurado, multiplicado por el tiempo de ejecución en segundos y el multiplicador de Function del nivel. Se acumula por separado para Function/herramientas personalizadas, incluidos los intentos de ejecución que fallan.

```javascript
executionCost = configuredWorkflowCharge * tierWorkflowExecutionMultiplier
adjustedModelCost = recordedModelCost * tierWorkflowModelCostMultiplier
workflowLogSubtotal = executionCost + sum(adjustedModelCost)
functionCost = (executionTimeMs / 1000) * configuredFunctionChargePerSecond * tierFunctionExecutionMultiplier
totalMeteredCost = workflowLogSubtotal + sum(functionCost)
```

Esta fórmula es ilustrativa. Cada cargo de Function se redondea a seis decimales. El total del registro del flujo de trabajo es el subtotal de ejecución/modelos; los cargos de Function acumulados por separado también contribuyen al uso del responsable de facturación. No son cargos de modelos de IA y pueden aplicarse a flujos de trabajo sin IA.

El trabajo de modelos ya realizado se contabiliza al guardar un punto de control de human-in-the-loop. Reanudar o cancelar no vuelve a cobrar ese mismo trabajo: cada ejecución lógica reutiliza su cotización de ejecución/modelos y aplica el cargo base de ejecución una sola vez. Los costos de un flujo hijo se contabilizan en su propio registro, sin volver a cobrarlos mediante las trazas anidadas del padre.

<Callout type="info">
  Para las ejecuciones cuya cotización se guarda por primera vez con la facturación deshabilitada, el cargo base es cero y los costos de modelos registrados usan un multiplicador de uno. Mientras la facturación está deshabilitada, no se acumula uso facturable adicional de flujos de trabajo ni de Function; las cotizaciones guardadas anteriormente no se modifican. La configuración de facturación, y no los valores fijos de esta guía, es la fuente de verdad para los cargos y los multiplicadores.
</Callout>

## Desglose de modelos en los registros

En los flujos de trabajo que usan bloques de IA, puedes consultar información detallada de costos en los registros:

La barra lateral de detalle del registro incluye una sección de desglose de modelos que muestra:
- **Uso de tokens**: recuento de tokens de entrada y de salida de cada modelo
- **Desglose de costos**: costo de entrada, de salida y total de cada modelo
- **Modelos utilizados**: qué modelos contribuyeron al costo de ejecución
- **Costo total**: subtotal de ejecución/modelos del registro; consulta el uso para ver los cargos de Function acumulados por separado

## Precios y límites

Los niveles de facturación disponibles y el catálogo de modelos se configuran en el despliegue de TradingGoose y pueden cambiar de forma independiente de esta documentación. Usa **Settings → Subscription** para consultar el uso actual, el límite de uso y los planes, precios y funciones anunciadas disponibles. La API de límites de uso que se describe a continuación informa valores de tasa, almacenamiento, retención y multiplicadores para el ámbito de facturación personal del usuario autenticado; no resuelve el nivel efectivo de una organización para un espacio de trabajo. Usa el selector de modelos del bloque Agent para ver los modelos disponibles actualmente en tu espacio de trabajo.

Si recibes un código de acceso para un nivel privado, ingrésalo en **Configuración → Suscripción**. Los códigos distinguen entre mayúsculas y minúsculas, aunque se ignoran los espacios en blanco alrededor. Un código válido habilita el plan privado correspondiente para tu usuario.

Un nivel de facturación también puede imponer una duración máxima a cada ejecución de flujo de trabajo en cola. La ejecución que alcanza ese límite se termina y se registra con el error `Workflow execution time limit exceeded`.

## Estrategias de optimización de costos

<Accordions>
  <Accordion title="Selección de modelo">
    Elige un modelo que se ajuste a la complejidad de la tarea y revisa el precio actual de su proveedor antes del despliegue.
  </Accordion>

  <Accordion title="Ingeniería de prompts">
    Los prompts bien estructurados y concisos reducen el uso de tokens sin sacrificar la calidad.
  </Accordion>

  <Accordion title="Modelos locales">
    Usa Ollama cuando un modelo local sea adecuado para evitar los cargos del proveedor externo de modelos. El cargo por ejecución de flujo de trabajo puede seguir aplicándose.
  </Accordion>

  <Accordion title="Caché y reutilización">
    Reutiliza las salidas de etapas anteriores o las variables del flujo de trabajo dentro de una ejecución en lugar de repetir llamadas al modelo de IA.
  </Accordion>

  <Accordion title="Procesamiento por lotes">
    Procesa varios elementos en una sola solicitud de IA en lugar de hacer llamadas individuales.
  </Accordion>
</Accordions>

## Monitoreo de uso

Monitorea tu uso y tu facturación en Configuración → Suscripción:

- **Uso actual**: Uso y costos acumulados en el periodo actual
- **Límite de uso**: El límite de gasto efectivo y el porcentaje consumido
- **Gestión del plan**: Acciones de suscripción disponibles cuando la facturación está habilitada

### Seguimiento programático del uso personal

Puedes consultar el uso personal y los límites del usuario autenticado de forma programática mediante la API:

**Endpoint:**

```text
GET /api/users/me/usage-limits
```

**Autenticación:**
- Incluye tu clave de API en el encabezado `X-API-Key`

**Solicitud de ejemplo:**

```bash
curl -X GET -H "X-API-Key: YOUR_API_KEY" -H "Content-Type: application/json" https://www.tradinggoose.ai/api/users/me/usage-limits
```

**Respuesta de ejemplo:**

```jsonc
{
  "success": true,
  "rateLimit": {
    "sync": { "isLimited": false, "limit": 10, "remaining": 10, "resetAt": "2025-09-08T22:51:55.999Z" },
    "async": { "isLimited": false, "limit": 50, "remaining": 50, "resetAt": "2025-09-08T22:51:56.155Z" },
    "authType": "api"
  },
  "usage": {
    "currentPeriodCost": 12.34,
    "limit": 100,
    "tier": {
      "id": "tier_example",
      "displayName": "Example Tier",
      "ownerType": "user",
      "usageScope": "individual",
      "syncRateLimitPerMinute": 10,
      "asyncRateLimitPerMinute": 50,
      "apiEndpointRateLimitPerMinute": 60,
      "logRetentionDays": 30,
      "workflowExecutionMultiplier": 1,
      "workflowModelCostMultiplier": 1
      // The response includes the remaining BillingTierSummary fields.
    }

  "storage": {
    "usedBytes": 5242880,
    "limitBytes": 1073741824,
    "percentUsed": 0.48828125

```

**Campos de la respuesta:**
- `currentPeriodCost` refleja el uso en el periodo de facturación actual
- `limit` es el límite de uso efectivo para el ámbito de facturación del usuario autenticado
- `tier` es el resumen completo del nivel de facturación, incluidos sus límites de velocidad configurados, la retención y los multiplicadores de costo
- `storage` informa el uso actual en bytes, el límite de bytes y el porcentaje utilizado

Los valores de ejemplo son ilustrativos. Lee la respuesta que se devuelve para tu cuenta en lugar de basarte en nombres de planes o límites fijos.

## Prácticas recomendadas para la gestión de costos

1. **Supervisa con regularidad**: Revisa con frecuencia tu panel de uso para evitar sorpresas
2. **Establece presupuestos**: Cuando tu plan lo permita, usa el límite de uso editable como barrera de gasto
3. **Optimiza los flujos de trabajo**: Revisa las ejecuciones de alto costo y optimiza los prompts o la selección del modelo
4. **Usa modelos adecuados**: Ajusta la complejidad del modelo a los requisitos de la tarea
5. **Agrupa tareas similares**: Combina varias solicitudes cuando sea posible para reducir la sobrecarga
