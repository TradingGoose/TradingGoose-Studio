TradingGoose aplica los cargos al responsable de facturación, usuario u organización, del espacio de trabajo autorizado. Los flujos de trabajo, Copilot y las llamadas independientes a modelos comparten el registro de uso y los límites de facturación de Studio.

## Cargos aplicados

- **Ejecución del flujo de trabajo**: combina el cargo base configurado y el multiplicador de ejecución del nivel con los costos de modelos y el multiplicador de modelos del nivel. Las liquidaciones repetidas solo añaden el uso recién completado. Los flujos hijos se liquidan por separado.
- **Tiempo de Function y herramientas personalizadas**: usa el cargo por segundo configurado y el multiplicador de Function del nivel, multiplicados por los milisegundos reales de ejecución y divididos entre 1000. Un intento que haya contactado el entorno puede generar este cargo aunque el código falle.
- **Trabajo de modelos y embeddings**: usa los tokens reportados y los precios estándar publicados en models.dev para los informes, la facturación del uso y los registros. Copilot aplica el multiplicador de costos de su nivel de suscripción de Studio al uso financiado por la cuenta; los cargos de modelos del flujo de trabajo se liquidan con el flujo.

Las comprobaciones de uso se realizan antes de contactar al modelo. Una solicitud puede fallar después de la generación si no se puede completar la facturación.

<Callout type="info">
  Los costos distinguen estimaciones, importes parciales y no disponibles. Un precio publicado de cero es distinto de un precio ausente. Los costos desconocidos no se presentan como un cero conocido.
</Callout>

## Uso e historial recargado

Los recuentos reportados de tokens de entrada, salida y totales siguen siendo opcionales. Las estimaciones de costos tienen en cuenta las categorías reportadas de tokens, incluidos los tokens de caché y razonamiento, y los niveles de contexto aplicables.

Las conversaciones de Copilot y el historial de Workflow Agent usan el mismo almacenamiento Mastra en la base de datos de Studio. Al recargar se conservan las partes de los mensajes, las llamadas a herramientas y sus resultados, y los metadatos disponibles de uso y costos del asistente. Records agrega los costos conocidos de modelos y herramientas; la cobertura incompleta sigue marcada como parcial o no disponible. Consulta **Configuración → Suscripción** para ver el uso aplicado del periodo actual.

## Precios y límites

Los niveles de facturación disponibles y el catálogo de modelos se configuran en el despliegue de TradingGoose y pueden cambiar de forma independiente de esta documentación. Usa **Settings → Subscription** para consultar el uso actual, el límite de uso y los planes, precios y funciones anunciadas disponibles. La API de límites de uso que se describe a continuación informa valores de tasa, almacenamiento, retención y multiplicadores para el ámbito de facturación personal del usuario autenticado; no resuelve el nivel efectivo de una organización para un espacio de trabajo. Usa el selector de modelos del bloque Agent para ver los modelos disponibles actualmente en tu espacio de trabajo.

Si recibes un código de acceso para un nivel privado, ingrésalo en **Configuración → Suscripción**. Los códigos distinguen entre mayúsculas y minúsculas, aunque se ignoran los espacios en blanco alrededor. Un código válido habilita el plan privado correspondiente para tu usuario.

Un nivel de facturación también puede imponer una duración máxima a cada ejecución de flujo de trabajo en cola. La ejecución que alcanza ese límite se termina y se registra con el error `Workflow execution time limit exceeded`.

## Monitoreo de uso

Monitorea tu uso y tu facturación en Configuración → Suscripción:

- **Uso actual**: Uso y costos acumulados en el periodo actual
- **Límite de uso**: El límite de gasto efectivo y el porcentaje consumido
- **Gestión del plan**: Acciones de suscripción disponibles cuando la facturación está habilitada

### Seguimiento programático del uso personal

Puedes consultar el uso personal y los límites del usuario autenticado de forma programática mediante la API:

**Endpoint:**

```text
GET /api/users/me/usage-limits
```

**Autenticación:**
- Incluye tu clave de API en el encabezado `X-API-Key`

**Solicitud de ejemplo:**

```bash
curl -X GET -H "X-API-Key: YOUR_API_KEY" -H "Content-Type: application/json" https://www.tradinggoose.ai/api/users/me/usage-limits
```

**Respuesta de ejemplo:**

`currentPeriodCost` y el `limit` monetario son números JSON en USD. El uso sin límite se representa con `9007199254740991` (`Number.MAX_SAFE_INTEGER`). Los precios y las asignaciones del nivel son números o `null` según la configuración; los multiplicadores de facturación son números.

```jsonc
{
  "success": true,
  "rateLimit": {
    "sync": { "isLimited": false, "limit": 10, "remaining": 10, "resetAt": "2025-09-08T22:51:55.999Z" },
    "async": { "isLimited": false, "limit": 50, "remaining": 50, "resetAt": "2025-09-08T22:51:56.155Z" },
    "authType": "api"
  },
  "usage": {
    "currentPeriodCost": 12.34,
    "limit": 100,
    "tier": {
      "id": "tier_example",
      "displayName": "Example Tier",
      "ownerType": "user",
      "usageScope": "individual",
      "syncRateLimitPerMinute": 10,
      "asyncRateLimitPerMinute": 50,
      "apiEndpointRateLimitPerMinute": 60,
      "logRetentionDays": 30,
      "workflowExecutionMultiplier": 1,
      "workflowModelCostMultiplier": 1
      // The response includes the remaining BillingTierSummary fields.
    }
  },
  "storage": {
    "usedBytes": 5242880,
    "limitBytes": 1073741824,
    "percentUsed": 0.48828125
  }
}
```

**Campos de la respuesta:**
- `currentPeriodCost` refleja el uso en el periodo de facturación actual
- `limit` es el límite de uso efectivo para el ámbito de facturación del usuario autenticado
- `tier` es el resumen completo del nivel de facturación, incluidos sus límites de velocidad configurados, la retención y los multiplicadores de costo
- `storage` informa el uso actual en bytes, el límite de bytes y el porcentaje utilizado

Los valores de ejemplo son ilustrativos. Lee la respuesta que se devuelve para tu cuenta en lugar de basarte en nombres de planes o límites fijos.

## Prácticas recomendadas para la gestión de costos

1. **Supervisa con regularidad**: Revisa con frecuencia tu panel de uso para evitar sorpresas
2. **Establece presupuestos**: Cuando tu plan lo permita, usa el límite de uso editable como barrera de gasto
3. **Optimiza los flujos de trabajo**: Revisa las ejecuciones de alto costo y optimiza los prompts o la selección del modelo
4. **Usa modelos adecuados**: Ajusta la complejidad del modelo a los requisitos de la tarea
5. **Agrupa tareas similares**: Combina varias solicitudes cuando sea posible para reducir la sobrecarga
