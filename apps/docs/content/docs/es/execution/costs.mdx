TradingGoose registra los cargos de producto aceptados para el responsable de facturación original del espacio de trabajo, ya sea usuario u organización. La política financiera compartida conserva el actor, el periodo de facturación y la cotización originales durante la ejecución y su reanudación.

## Cargos aplicados

- **Ejecución del flujo de trabajo**: usa el cargo base y el multiplicador de ejecución del nivel guardados en la cotización original. Cada ejecución lógica liquida su cargo base una sola vez. Los flujos hijos se liquidan por separado.
- **Tiempo de Function y herramientas personalizadas**: usa el cargo por segundo y el multiplicador de Function guardados, multiplicados por los milisegundos reales de ejecución y divididos entre 1000. Un intento que haya contactado el entorno puede generar este cargo aunque el código falle.
- **Trabajo de modelos y embeddings**: requiere admisión financiera y aceptación verificada para cada paso o lote real. El costo genérico en USD de los modelos nativos no está disponible en la integración actual. Los tokens no determinan un cargo en dólares y un precio ausente nunca se interpreta como cero conocido.

Los importes, límites, asignaciones, multiplicadores y recibos usan cadenas decimales exactas. Los cargos de Function conservan toda su precisión, sin cuantización a seis decimales. La presentación monetaria puede redondear para facilitar la lectura. Al emitir la factura, USD se convierte a centavos con la regla documentada de redondeo a la mitad hacia arriba; esta conversión no modifica el registro de uso.

La finalización requiere aceptación financiera verificada y lectura autorizada de la salida canónica. Un fallo financiero o de lectura puede impedir entregar el resultado como exitoso aunque el trabajo haya terminado; no autoriza repetir ese trabajo. La reanudación conserva la identidad financiera y las operaciones aceptadas sin volver a cobrar el mismo trabajo. Los puntos de revisión humana conservan esa identidad.

<Callout type="info">
  Consulta el uso realmente aceptado y la cotización guardada para obtener los datos de facturación. Un cargo cero configurado y verificado es distinto de un costo de modelo no disponible. Cambiar la configuración no reescribe una cotización, un responsable ni un periodo existentes.
</Callout>

## Uso activo y registros recargados

Durante una solicitud activa, los resultados nativos pueden incluir recuentos opcionales de tokens de entrada, salida o totales y el modelo seleccionado. Los contadores ausentes siguen sin estar disponibles. El costo genérico en USD se etiqueta como no disponible, sin tablas manuales de precios ni estimaciones basadas en tokens.

Al recargar Records se conservan las entradas, salidas, herramientas y detalles funcionales mediante almacenamiento canónico autorizado. Los diagnósticos del proveedor, informes de costos de modelos y totales de tokens por turno no son informes duraderos del producto. La recarga no reconstruye un desglose de costos a partir de trazas o del tamaño de la conversación. Consulta **Configuración → Suscripción** para ver el uso realmente aplicado del periodo; un subtotal de modelos visible no es el registro financiero.

## Precios y límites

Los niveles de facturación disponibles y el catálogo de modelos se configuran en el despliegue de TradingGoose y pueden cambiar de forma independiente de esta documentación. Usa **Settings → Subscription** para consultar el uso actual, el límite de uso y los planes, precios y funciones anunciadas disponibles. La API de límites de uso que se describe a continuación informa valores de tasa, almacenamiento, retención y multiplicadores para el ámbito de facturación personal del usuario autenticado; no resuelve el nivel efectivo de una organización para un espacio de trabajo. Usa el selector de modelos del bloque Agent para ver los modelos disponibles actualmente en tu espacio de trabajo.

Si recibes un código de acceso para un nivel privado, ingrésalo en **Configuración → Suscripción**. Los códigos distinguen entre mayúsculas y minúsculas, aunque se ignoran los espacios en blanco alrededor. Un código válido habilita el plan privado correspondiente para tu usuario.

Un nivel de facturación también puede imponer una duración máxima a cada ejecución de flujo de trabajo en cola. La ejecución que alcanza ese límite se termina y se registra con el error `Workflow execution time limit exceeded`.

## Monitoreo de uso

Monitorea tu uso y tu facturación en Configuración → Suscripción:

- **Uso actual**: Uso y costos acumulados en el periodo actual
- **Límite de uso**: El límite de gasto efectivo y el porcentaje consumido
- **Gestión del plan**: Acciones de suscripción disponibles cuando la facturación está habilitada

### Seguimiento programático del uso personal

Puedes consultar el uso personal y los límites del usuario autenticado de forma programática mediante la API:

**Endpoint:**

```text
GET /api/users/me/usage-limits
```

**Autenticación:**
- Incluye tu clave de API en el encabezado `X-API-Key`

**Solicitud de ejemplo:**

```bash
curl -X GET -H "X-API-Key: YOUR_API_KEY" -H "Content-Type: application/json" https://www.tradinggoose.ai/api/users/me/usage-limits
```

**Respuesta de ejemplo:**

**Cambio incompatible del ABI monetario:** `currentPeriodCost` es texto decimal exacto en USD, por ejemplo `"9007199254740993.30000000000000001"`; el `limit` monetario es una cadena decimal o `null` para un límite ilimitado. Los precios, asignaciones y multiplicadores del nivel también son cadenas decimales o `null` según la configuración. Conserva estos valores sin convertirlos con `Number`/`float`. Los contadores de velocidad, plazas y campos de almacenamiento siguen siendo numéricos.

```jsonc
{
  "success": true,
  "rateLimit": {
    "sync": { "isLimited": false, "limit": 10, "remaining": 10, "resetAt": "2025-09-08T22:51:55.999Z" },
    "async": { "isLimited": false, "limit": 50, "remaining": 50, "resetAt": "2025-09-08T22:51:56.155Z" },
    "authType": "api"
  },
  "usage": {
    "currentPeriodCost": "12.34",
    "limit": "100",
    "tier": {
      "id": "tier_example",
      "displayName": "Example Tier",
      "ownerType": "user",
      "usageScope": "individual",
      "syncRateLimitPerMinute": 10,
      "asyncRateLimitPerMinute": 50,
      "apiEndpointRateLimitPerMinute": 60,
      "logRetentionDays": 30,
      "workflowExecutionMultiplier": "1",
      "workflowModelCostMultiplier": "1"
      // The response includes the remaining BillingTierSummary fields.
    }
  },
  "storage": {
    "usedBytes": 5242880,
    "limitBytes": 1073741824,
    "percentUsed": 0.48828125
  }
}
```

**Campos de la respuesta:**
- `currentPeriodCost` refleja el uso en el periodo de facturación actual
- `limit` es el límite de uso efectivo para el ámbito de facturación del usuario autenticado
- `tier` es el resumen completo del nivel de facturación, incluidos sus límites de velocidad configurados, la retención y los multiplicadores de costo
- `storage` informa el uso actual en bytes, el límite de bytes y el porcentaje utilizado

Los valores de ejemplo son ilustrativos. Lee la respuesta que se devuelve para tu cuenta en lugar de basarte en nombres de planes o límites fijos.

## Prácticas recomendadas para la gestión de costos

1. **Supervisa con regularidad**: Revisa con frecuencia tu panel de uso para evitar sorpresas
2. **Establece presupuestos**: Cuando tu plan lo permita, usa el límite de uso editable como barrera de gasto
3. **Optimiza los flujos de trabajo**: Revisa las ejecuciones de alto costo y optimiza los prompts o la selección del modelo
4. **Usa modelos adecuados**: Ajusta la complejidad del modelo a los requisitos de la tarea
5. **Agrupa tareas similares**: Combina varias solicitudes cuando sea posible para reducir la sobrecarga
