Coloca un bloque de flujo de trabajo cuando quieras llamar a un flujo de trabajo secundario como parte de un flujo más grande. El bloque ejecuta la última versión desplegada de ese flujo de trabajo, espera a que termine y luego continúa con el flujo principal.

## Cómo configurarlo

1. **Elige un flujo de trabajo** en el menú desplegable (las autorreferencias están bloqueadas para evitar bucles).
2. **Asigna las entradas**: si el flujo de trabajo secundario tiene un disparador de Formulario de entrada, verás cada campo y podrás conectar variables del flujo principal. Los valores asignados son los que recibe el flujo secundario.
3. **Salidas**: cuando el flujo secundario termina, el bloque expone:
   - `result` – la respuesta final del flujo de trabajo secundario
   - `success` – si se ejecutó sin errores
   - `error` – mensaje cuando falla la ejecución

## Notas de ejecución

- Los flujos de trabajo secundarios se ejecutan en el mismo contexto de espacio de trabajo, por lo que las variables de entorno y las herramientas se mantienen.
- El bloque usa el versionado de despliegue: cualquier ejecución por API, programación, webhook, manual o chat llama a la instantánea desplegada. Vuelve a desplegar el flujo secundario cuando lo modifiques.
- Si el flujo secundario falla, el bloque genera un error a menos que lo gestiones en las etapas posteriores.

<Callout>
Mantén los flujos de trabajo hijos enfocados. Los flujos pequeños y reutilizables facilitan combinarlos sin crear un anidamiento profundo.
</Callout>
