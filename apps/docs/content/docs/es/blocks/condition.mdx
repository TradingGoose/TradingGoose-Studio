El bloque Condición te permite ramificar la ruta de ejecución de tu flujo de trabajo según expresiones booleanas, lo que te permite crear flujos de trabajo dinámicos y adaptables con diferentes rutas de ejecución. Evalúa condiciones y dirige el flujo de trabajo en consecuencia, permitiéndote controlar el flujo de ejecución según datos o lógica sin necesidad de un LLM.

## Descripción general

El bloque Condición te permite:

  </Step>
  <Step>
    <strong>Manejar múltiples escenarios</strong>: Define múltiples condiciones con diferentes rutas

  </Step>

## Cómo funciona

El bloque Condición opera mediante un proceso de evaluación secuencial:

1. **Evaluar expresión** - Procesa la expresión booleana de JavaScript/TypeScript usando los datos actuales del flujo de trabajo
2. **Determinar resultado** - Devuelve verdadero o falso según la evaluación de la expresión
3. **Enrutar flujo de trabajo** - Dirige la ejecución al bloque de destino adecuado según el resultado
4. **Proporcionar contexto** - Genera metadatos sobre la decisión para depuración y monitoreo

## Opciones de configuración

### Condiciones

Define una o más condiciones que se evaluarán. Cada condición incluye:

- **Expresión**: Una expresión de JavaScript/TypeScript que se evalúa como verdadero o falso
- **Ruta**: El bloque de destino al que enrutar si la condición es verdadera
- **Descripción**: Explicación opcional de lo que verifica la condición

Puedes crear múltiples condiciones que se evalúan en orden, y la primera condición que coincida determina la ruta de ejecución.

### Formato de expresión de condición

Las condiciones usan sintaxis de JavaScript y pueden hacer referencia a valores de entrada de bloques anteriores.

### Acceder a los resultados

Después de que se evalúa una condición, puedes acceder a sus salidas:

- **`<condition.result>`**: Resultado booleano de la evaluación de la condición
- **`<condition.matched_condition>`**: ID de la condición que coincidió
- **`<condition.content>`**: Descripción del resultado de la evaluación
- **`<condition.path>`**: Detalles del destino de enrutamiento elegido

## Funciones avanzadas

### Expresiones complejas

Usa operadores y funciones de JavaScript en las condiciones:

```javascript
// String operations
<user.email>.endsWith('@company.com')

// Array operations
<api.tags>.includes('urgent')

// Mathematical operations
<agent.confidence> * 100 > 85

// Date comparisons
new Date(<api.created_at>) > new Date('2024-01-01')
```

### Evaluación de múltiples condiciones

Las condiciones se evalúan en orden hasta que una coincida:

```javascript
// Condition 1: Check for high priority
<ticket.priority> === 'high'

// Condition 2: Check for urgent keywords
<ticket.subject>.toLowerCase().includes('urgent')

// Condition 3: Default fallback
true
```

### Manejo de errores

Las condiciones gestionan automáticamente:
- Valores indefinidos o nulos con evaluación segura
- Incompatibilidades de tipo con alternativas adecuadas
- Expresiones no válidas con registro de errores
- Variables ausentes con valores predeterminados

## Buenas prácticas

- **Ordena las condiciones correctamente**: Coloca las condiciones más específicas antes de las generales para que la lógica específica tenga prioridad sobre los casos de respaldo
- **Incluye una condición predeterminada**: Agrega una condición general (`true`) como última condición para manejar los casos no coincidentes y evitar que la ejecución del flujo de trabajo se quede bloqueada
- **Mantén las expresiones simples**: Usa expresiones booleanas claras y directas para mejorar la legibilidad y facilitar la depuración
- **Documenta tus condiciones**: Agrega descripciones que expliquen el propósito de cada condición para mejorar la colaboración y el mantenimiento del equipo
- **Prueba los casos límite**: Verifica que las condiciones manejen correctamente los valores límite probando con valores en los extremos de tus rangos de condiciones
