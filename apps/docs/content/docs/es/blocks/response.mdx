## Descripción general

El bloque Response te permite:

<Steps>
  <Step>
    <strong>Formatear respuestas de API</strong>: Estructura los resultados del flujo de trabajo en respuestas HTTP adecuadas
  </Step>
  <Step>
    <strong>Definir códigos de estado</strong>: Configura los códigos de estado HTTP adecuados según los resultados del flujo de trabajo
  </Step>
  <Step>
    <strong>Controlar encabezados</strong>: Añade encabezados personalizados para respuestas de API y webhooks
  </Step>
  <Step>
    <strong>Transformar datos</strong>: Convierte variables del flujo de trabajo en formatos de respuesta aptos para el cliente
  </Step>
</Steps>

## Cómo funciona

El bloque Response finaliza la ejecución del flujo de trabajo:

1. **Recopilar datos** - Reúne variables y salidas de bloques anteriores
2. **Formatear la respuesta** - Estructura los datos según tu configuración
3. **Definir los detalles HTTP** - Aplica códigos de estado y encabezados
4. **Enviar la respuesta** - Devuelve la respuesta formateada al llamador de la API

## Cuándo necesitas bloques Response

- **Endpoints de API**: cuando se llama a tu flujo de trabajo mediante API, los bloques Response formatean los datos de retorno
- **Webhooks**: devuelven una confirmación o datos al sistema que realiza la llamada
- **Pruebas**: consulta los resultados formateados al probar tu flujo de trabajo

## Dos formas de crear respuestas

### Modo Builder (recomendado)
Interfaz visual para crear la estructura de la respuesta:
- Arrastra y suelta campos
- Haz referencia a variables del flujo de trabajo fácilmente
- Vista previa visual de la estructura de la respuesta

### Modo Editor (avanzado)
Escribe JSON directamente:
- Control total sobre el formato de la respuesta
- Compatibilidad con estructuras anidadas complejas
- Usa la sintaxis `<variable.name>` para valores dinámicos

## Opciones de configuración

### Datos de la respuesta

Los datos de la respuesta son el contenido principal que se enviará de vuelta al llamador de la API. Deben tener formato JSON y pueden incluir:

- Valores estáticos
- Referencias dinámicas a variables del flujo de trabajo mediante la sintaxis `<variable.name>`
- Objetos y matrices anidados
- Cualquier estructura JSON válida

### Código de estado

Define el código de estado HTTP para la respuesta. Los códigos de estado comunes incluyen:

### Encabezados de respuesta

Configura encabezados HTTP adicionales para incluir en la respuesta.

Los encabezados se configuran como pares clave-valor:

| Clave | Valor |
|-----|-------|
| Content-Type | application/json |
| Cache-Control | no-cache |
| X-API-Version | 1.0 |

## Referencias a variables

Usa la sintaxis `<variable.name>` para insertar dinámicamente variables del workflow en tu respuesta:

```json
{
  "user": {
    "id": "<variable.userId>",
    "name": "<variable.userName>",
    "email": "<variable.userEmail>"
  },
  "query": "<variable.searchQuery>",
  "results": "<variable.searchResults>",
  "totalFound": "<variable.resultCount>",
  "processingTime": "<variable.executionTime>ms"
}
```

<Callout type="warning">
  Los nombres de las variables distinguen mayúsculas y minúsculas y deben coincidir exactamente con las variables disponibles en tu workflow.
</Callout>

## Buenas prácticas

- **Usa códigos de estado significativos**: elige códigos de estado HTTP adecuados que reflejen con precisión el resultado del workflow
- **Estructura tus respuestas de forma coherente**: mantén una estructura JSON coherente en todos los endpoints de tu API para mejorar la experiencia del desarrollador
- **Incluye metadatos relevantes**: agrega marcas de tiempo e información de versión para facilitar la depuración y el monitoreo
- **Maneja los errores correctamente**: usa lógica condicional en tu workflow para definir respuestas de error adecuadas con mensajes descriptivos
- **Valida las referencias a variables**: asegúrate de que todas las variables referenciadas existan y contengan los tipos de datos esperados antes de que se ejecute el bloque Response
