El bloque Router usa IA para decidir de forma inteligente qué ruta debe tomar tu workflow a continuación, dirigiendo la ejecución del workflow según condiciones o lógica específicas. A diferencia de los bloques Condition, que usan reglas simples, los bloques Router pueden entender el contexto y tomar decisiones de enrutamiento inteligentes basadas en el análisis del contenido.

## Descripción general

El bloque Router te permite:

<Steps>
  <Step>
    <strong>Enrutamiento inteligente de contenido</strong>: Usa IA para entender la intención y el contexto
  </Step>
  <Step>
    <strong>Selección dinámica de rutas</strong>: Enruta workflows según el análisis de contenido no estructurado
  </Step>
  <Step>
    <strong>Decisiones con contexto</strong>: Toma decisiones de enrutamiento inteligentes más allá de las reglas simples
  </Step>
  <Step>
    <strong>Gestión de múltiples rutas</strong>: Maneja workflows complejos con múltiples destinos posibles
  </Step>
</Steps>

## Router vs Bloques Condition

<Accordions>
  <Accordion title="Cuándo usar Router">
    - Se necesita análisis de contenido con IA
    - Tipos de contenido no estructurados o variables
    - Enrutamiento basado en intención (p. ej., "enrutar tickets de soporte a departamentos")
    - Se requiere toma de decisiones consciente del contexto
  </Accordion>
  <Accordion title="Cuándo usar Condition">
    - Decisiones simples basadas en reglas
    - Datos estructurados o comparaciones numéricas
    - Se necesita enrutamiento rápido y determinista
    - Lógica booleana suficiente
  </Accordion>
</Accordions>

## Cómo funciona

El bloque Router:

<Steps>
  <Step>
    <strong>Analizar contenido</strong>: Utiliza un LLM para comprender el contenido de entrada y el contexto
  </Step>
  <Step>
    <strong>Evaluar destinos</strong>: Compara el contenido con los bloques de destino disponibles
  </Step>
  <Step>
    <strong>Seleccionar destino</strong>: Identifica la ruta más adecuada según la intención
  </Step>
  <Step>
    <strong>Enrutar ejecución</strong>: Dirige el flujo de trabajo al bloque seleccionado
  </Step>
</Steps>

## Opciones de configuración

### Contenido/Prompt

El contenido o prompt que el Router analizará para tomar decisiones de enrutamiento. Puede ser:

- Una consulta o entrada directa del usuario
- Salida de un bloque anterior
- Un mensaje generado por el sistema

### Bloques de destino

Router elige entre los bloques de destino conectados. Usa nombres claros y explica los criterios de enrutamiento en el prompt de Router. Para excluir un destino, elimina su conexión; no existe un ajuste de exclusión por destino.

### Selección de modelo

Elige un modelo disponible en el selector actual y configura las credenciales de su proveedor. La disponibilidad depende de la configuración de tu instancia.

### Clave de API

Tu clave de API para el proveedor de LLM seleccionado. Se almacena de forma segura y se utiliza para la autenticación.

### Acceso a los resultados

Después de que un enrutador toma una decisión, puedes acceder a sus salidas:

- **`<router.prompt>`**: El prompt de enrutamiento original
- **`<router.selectedPath>`**: Detalles del bloque de destino elegido
- **`<router.tokens>`**: Estadísticas de uso de tokens del LLM
- **`<router.cost>`**: Resumen de costos de la llamada de enrutamiento (entrada, salida, total)
- **`<router.model>`**: El modelo utilizado para la toma de decisiones

## Buenas prácticas

- **Proporciona descripciones claras de los destinos**: Ayuda al Router a entender cuándo seleccionar cada destino con descripciones específicas y detalladas
- **Usa criterios de enrutamiento específicos**: Define condiciones y ejemplos claros para cada ruta a fin de mejorar la precisión
- **Implementa rutas de reserva**: Conecta un destino predeterminado para cuando ninguna ruta específica sea adecuada
- **Prueba con entradas diversas**: Asegúrate de que el Router gestione distintos tipos de entrada, casos límite y contenido inesperado
- **Supervisa el rendimiento del enrutamiento**: Revisa las decisiones de enrutamiento con regularidad y ajusta los criterios según los patrones de uso reales
- **Elige modelos adecuados**: Usa modelos con sólidas capacidades de razonamiento para decisiones de enrutamiento complejas
