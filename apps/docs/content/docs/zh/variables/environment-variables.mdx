title: 环境变量
---

import { Callout } from 'fumadocs-ui/components/callout'

环境变量提供了一种安全方式，可在多个工作流中管理配置值和机密信息，包括 API 密钥以及工作流需要访问的其他敏感数据。机密信息不会写入工作流定义，但在执行期间仍可使用。

## 变量类型

TradingGoose 中的环境变量分为两个级别：

- **个人环境变量**：仅对你的账户可见，只有你可以查看和使用。
- **工作区环境变量**：在整个工作区中共享，所有团队成员均可使用。

<Callout type="info">
发生命名冲突时，工作区环境变量优先于个人环境变量。
</Callout>

## 设置环境变量

前往 **Settings** 配置环境变量。你可以在工作区设置中创建和管理个人环境变量及工作区环境变量。个人变量仅对你的账户可见，工作区变量则与所有团队成员共享。

### 将变量设为工作区范围

使用工作区范围开关，使变量可供整个团队使用。启用工作区范围后，所有工作区成员都能使用该变量，并可在该工作区的任何工作流中引用它。

### 工作区变量视图

创建工作区范围的变量后，它们会与个人变量一起显示在环境变量列表中，并清楚标注各自的范围。

## 在工作流中使用变量

使用 `{{}}` 表示法在工作流中引用环境变量。在任何输入字段中输入 `{{` 时，会显示一个下拉列表，其中包含个人环境变量和工作区环境变量。直接选择要使用的变量即可。

## 变量优先级

个人变量和工作区变量同名时：

1. **工作区变量优先于个人变量**。
2. 这可以避免命名冲突，并确保团队工作流的行为保持一致。
3. 如果工作区变量已存在，则忽略同名的个人变量。

<Callout type="warning">
请谨慎选择变量名称，以免发生意外覆盖。可以为个人变量添加你的姓名首字母前缀，或为工作区变量添加项目名称前缀。
</Callout>

## 安全最佳实践

### 敏感数据
- 将 API 密钥、令牌和密码存储为环境变量，不要直接写入代码。
- 多个团队成员需要使用共享资源时，请使用工作区变量。
- 将个人凭据保存在个人变量中。

### 变量命名
- 使用描述性名称：使用 `DATABASE_URL`，不要使用 `DB`。
- 在整个团队中采用一致的命名约定。
- 考虑使用前缀避免冲突：`PROD_API_KEY`、`DEV_API_KEY`。

### 访问控制
- 工作区环境变量遵循工作区权限。
- 只有具备写入或更高权限的用户才能创建或修改工作区变量。
- 个人变量始终只对对应用户可见。
