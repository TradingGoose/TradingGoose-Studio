API 触发器会将工作流公开为安全的 HTTP 端点。向端点发送 JSON 数据后，工作流会立即处理。API 调用始终使用最新部署。

<Callout type="info">
  此为 一个 **webhook-based** trigger. 外部 services或scripts 发送 HTTP 请求到开始 workflow.
</Callout>

添加一个 **输入格式** 字段，用于每个参数. Supported 类型:

- **字符串** — 文本值
- **数字** — Numeric 值
- **布尔值** — True/false 值
- **json** — JSON 对象
- **文件** — 文件 uploads (访问 via `<api.fieldName[0].url>`, `<api.fieldName[0].name>`, etc.)

### 输出 Reference

| Reference | 类型 | 描述 |
|-----------|------|-------------|
| `<api.field>` | varies | 字段 defined在输入格式 |
| `<api.input>` | json | Entire structured 请求正文 |

## 请求示例

```bash
curl -X POST \
  https://tradinggoose.ai/api/workflows/WORKFLOW_ID/execute \
  -H 'Content-Type: application/json' \
  -H 'X-API-Key: YOUR_KEY' \
  -d '{"userId":"demo-user","maxTokens":1024}'
```

## 流式响应

启用实时流式传输，以便在工作流生成输出时立即接收。

### 请求参数

- `stream` — 设置为 `true` 可启用服务器发送事件（SSE）流式传输
- `selectedOutputs` — 要以流式方式传输的模块输出数组（例如 `["agent1.content"]`）

### 示例

```bash
curl -X POST \
  https://tradinggoose.ai/api/workflows/WORKFLOW_ID/execute \
  -H 'Content-Type: application/json' \
  -H 'X-API-Key: YOUR_KEY' \
  -d '{"message": "Count to five", "stream": true, "selectedOutputs": ["agent1.content"]}'
```

### 响应格式

```
data: {"blockId":"...","chunk":"One"}
data: {"blockId":"...","chunk":", two"}
data: {"event":"done","success":true,"output":{},"metadata":{"duration":610}}
data: [DONE]
```

### 文件上传格式

```json
{
  "documents": [{
    "type": "file",
    "data": "data:application/pdf;base64,JVBERi0xLjQK...",
    "name": "document.pdf",
    "mime": "application/pdf"
  }]
}
```

<Callout type="warning">
A workflow 可包含仅 一个 API trigger. 发布一个新建 deployment 之后 changes 因此端点 stays 上到日期.
</Callout>
