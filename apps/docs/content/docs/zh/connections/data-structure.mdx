当你连接模块时，了解不同模块输出的数据结构很重要，因为源模块的输出数据结构决定了目标模块中可用的值。每种模块类型都会生成特定的输出结构，你可以在下游模块中引用。

<Callout type="info">
  理解这些数据结构对于在工作流中有效使用连接标签和访问正确的数据至关重要。
</Callout>

## 模块输出结构

不同模块类型会生成不同的输出结构。以下是每种模块类型的输出说明：

<Tabs items={['智能体输出', 'API输出', '函数输出', '评估器输出', '条件输出', '路由输出']}>
  <Tab>

    ```json
    {
      "content": "The generated text response",
      "model": "gpt-4o",
      "tokens": {
        "prompt": 120,
        "completion": 85,
        "total": 205
      },
      "toolCalls": [...],
      "cost": [...],
      "usage": [...]
    }
    ```

### 智能体模块输出字段

    - **content**：智能体生成的主要文本响应
    - **model**：所使用的AI模型（例如 “gpt-4o”、“claude-3-opus”）
    - **tokens**：Token使用统计
      - **prompt**：提示词中的Token数量
      - **completion**：补全中的Token数量
      - **total**：使用的总Token数量
    - **toolCalls**：智能体发起的工具调用数组（如有）
    - **cost**：每次工具调用的成本对象数组（如有）
    - **usage**：整个响应的Token使用统计

  </Tab>
  <Tab>

    ```json
    {
      "data": "Response data",
      "status": 200,
      "headers": {
        "content-type": "application/json",
        "cache-control": "no-cache"
      }
    }
    ```

### API模块输出字段

    - **data**：API返回的响应数据（可以是任何类型）
    - **status**：响应的HTTP状态码
    - **headers**：API返回的HTTP响应头

  </Tab>
  <Tab>

    ```json
    {
      "result": "Function return value",
      "stdout": "Console output",
    }
    ```

### 函数模块输出字段

    - **result**：函数的返回值（可以是任何类型）
    - **stdout**：函数执行期间捕获的控制台输出

  </Tab>
  <Tab>

    ```json
    {
      "content": "Evaluation summary",
      "model": "gpt-5",
      "tokens": {
        "prompt": 120,
        "completion": 85,
        "total": 205
      },
      "metric1": 8.5,
      "metric2": 7.2,
      "metric3": 9.0
    }
    ```

    ### 评估器块输出字段

    - **content**: 评估摘要
    - **model**: 用于评估的 AI 模型
    - **tokens**: Token 使用统计
    - **[metricName]**: 评估器中定义的每个指标的得分（动态字段）

  </Tab>
  <Tab>

    ```json
    {
      "content": "Original content passed through",
      "conditionResult": true,
      "selectedPath": {
        "blockId": "2acd9007-27e8-4510-a487-73d3b825e7c1",
        "blockType": "agent",
        "blockTitle": "Follow-up Agent"
      },
      "selectedConditionId": "condition-1"
    }
    ```

    ### 条件块输出字段

    - **content**: 传递的原始内容
    - **conditionResult**: 条件评估的布尔结果
    - **selectedPath**: 有关所选路径的信息
      - **blockId**: 所选路径中下一个块的 ID
      - **blockType**: 下一个块的类型
      - **blockTitle**: 下一个块的标题
    - **selectedConditionId**: 所选条件的 ID

  </Tab>
  <Tab>

    ```json
    {
      "content": "Routing decision",
      "model": "gpt-4o",
      "tokens": {
        "prompt": 120,
        "completion": 85,
        "total": 205
      },
      "selectedPath": {
        "blockId": "2acd9007-27e8-4510-a487-73d3b825e7c1",
        "blockType": "agent",
        "blockTitle": "Customer Service Agent"
      }
    }
    ```

    ### 路由块输出字段

    - **content**: 路由决策文本
    - **model**: 用于路由的 AI 模型
    - **tokens**: Token 使用统计
    - **selectedPath**: 有关所选路径的信息
      - **blockId**: 所选目标块的 ID
      - **blockType**: 所选块的类型
      - **blockTitle**: 所选块的标题

  </Tab>
</Tabs>

## 自定义输出结构

某些块可能会根据其配置生成自定义输出结构：

1. **带响应格式的智能体块**：在智能体块中使用响应格式时，输出结构将与定义的架构匹配，而不是标准结构。

2. **函数块**：`result` 字段可以包含函数代码返回的任何数据结构。

3. **API 块**：`data` 字段将包含 API 返回的任何内容，可以是任何有效的 JSON 结构。

<Callout type="warning">
  在开发过程中，请务必检查块的实际输出结构，以确保在连接中
  引用正确的字段。
</Callout>

## 嵌套数据结构

许多区块输出包含嵌套数据结构。您可以使用点表示法在连接标签中访问它们：

```
<blockName.path.to.nested.data>
```

例如：

- `<agent1.tokens.total>` - 访问来自 Agent 区块的总令牌数
- `<api1.data.results[0].id>` - 访问来自 API 响应的第一个结果的 ID
- `<function1.result.calculations.total>` - 访问 Function 区块结果中的嵌套字段
