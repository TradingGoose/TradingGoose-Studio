技能是定义 Agent 块专用行为的可复用指令集。技能只需创建一次，即可附加到同一工作区中任意工作流的任意代理。技能使用 TradingGoose 共享导出 JSON 格式，因此可以从技能编辑器导出，并通过技能列表组件导入。

## 技能定义

每项技能都存储为 `SkillDefinition`，包含四个面向用户的字段：

| 字段 | 规则 | 用途 |
|---|---|---|
| **name** | 1 至 64 个字符，保存时去除首尾空格 | 工作区中的唯一标识符 |
| **description** | 1 至 1024 个字符 | 向代理和团队成员说明技能的用途 |
| **content** | 1 至 50 000 个字符 | 完整提示：指令、上下文、规则和示例 |
| **id** | 自动生成 | API 和存储使用的不可变引用 |

每项技能还包含 `workspaceId`、`userId`、`createdAt` 和可选的 `updatedAt` 时间戳。

## 创建和编辑技能

<Steps>
  <Step>
    在工作区中打开[技能编辑器](/widgets/editor-skill)组件。
  </Step>
  <Step>
    输入最多 64 个字符的**名称**、简短的**说明**以及完整的**内容**，即代理应遵循的指令。
  </Step>
  <Step>
    **保存**技能。API 会验证所有字段，并拒绝同一工作区中的重复项。
  </Step>
</Steps>

要更新现有技能，请在技能编辑器中选择它，修改任意字段并保存。引用该技能的所有工作流都会在下次运行时使用新内容。

要删除技能，请使用技能编辑器中的删除操作。删除操作需要工作区的 `admin` 或 `write` 权限。

## 导入和导出

技能使用 TradingGoose 共享导出 JSON 格式。从技能编辑器导出技能，然后通过[技能列表](/widgets/list-skill)组件导入。导入的技能会自动规范化，重复名称会被重命名，因此无需手动清理即可在工作区之间移动技能。

## 在 Agent 块中使用技能

Agent 块提供 **Skills** 输入（`skill-input` 类型）。配置时，从工作区选择一项或多项技能。运行时，代理会在系统提示和用户提示之外，将每项所选技能的内容作为附加指令接收。

<Callout type="info">
  技能的作用域为工作区。所有能访问工作区的团队成员都可以浏览和使用技能；具备写入权限的成员还可以编辑或删除技能。
</Callout>

## 技能在运行时的工作方式

1. 工作流执行器读取代理的 `skills` 输入，即所选技能引用的数组。
2. 技能存储（`useSkillsStore`）使用 `getSkill(id, workspaceId)`，在活动工作区中解析每个引用。
3. 调用 LLM 前，解析后的技能内容会合并到代理的提示上下文中。

存储按工作区为技能建立索引（`skillsByWorkspace`），因此切换工作区时会立即加载正确的技能集。

## 权限

| 操作 | 所需权限 |
|---|---|
| 列出或读取技能 | 任意工作区访问权限 |
| 创建、更新或删除 | `admin` 或 `write` |

## 最佳实践

- **每个角色使用一项技能**：让每项技能专注于单一角色或任务类型。
- 在内容中**包含示例**，用于约束代理行为。
- **原位迭代**：编辑技能会更新引用它的所有工作流，无需重新连接。
- **使用描述性名称**：保持简短、去除首尾空格，并确保在工作区中唯一。
