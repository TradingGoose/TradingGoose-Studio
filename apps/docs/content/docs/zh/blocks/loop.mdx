Loop 块是一个容器，可重复执行其中的块。它不是具有独立源文件的普通块，而是由执行器的 `LoopBlockHandler` 管理的特殊包装节点。将块拖入循环容器后，这些块会在每次迭代中运行一次。

<Callout type="info">
  Loop 块是容器节点。请在画布上将子块拖入循环。入站边通过 Loop Start 进入；子块输出重新连接到 Loop End，随后 workflow 才会在循环外继续执行。
</Callout>

## 循环类型

<Tabs items={['For', 'ForEach', 'While', 'Do-While']}>
  <Tab>
    **For 循环** -- 运行固定次数。未指定时，默认迭代次数为 **5**。

    ```
    Example: Run 3 times
    - Iteration 1 (index 0)
    - Iteration 2 (index 1)
    - Iteration 3 (index 2)
    ```
  </Tab>
  <Tab>
    **ForEach 循环** -- 遍历数组或对象中的每一项。集合不能为空；空集合会引发错误。

    ```
    Example: Process ["apple", "banana", "orange"]
    - Iteration 1: currentItem = "apple"
    - Iteration 2: currentItem = "banana"
    - Iteration 3: currentItem = "orange"
    ```

    对于对象，每次迭代都会收到一个 `[key, value]` 对。
  </Tab>
  <Tab>
    **While 循环** -- 在每次迭代**之前**评估条件。如果第一次检查时条件为假，则不会执行循环体。

    While 和 Do-While 循环**没有内置迭代上限**。它们依靠条件变为假或 workflow 超时来停止。
  </Tab>
  <Tab>
    **Do-While 循环** -- 至少执行一次循环体，然后在每次迭代**之后**评估条件。需要先执行一次再检查条件时使用。
  </Tab>
</Tabs>

## 工作原理

执行器的 `LoopBlockHandler` 管理迭代控制：

1. **初始化** -- 循环计数器从 1 开始。对于 `forEach` 循环，系统会解析集合（JSON、变量引用或表达式）。
2. **检查是否继续** -- `for` 和 `forEach` 将计数器与集合长度或迭代次数进行比较。`while` 和 `doWhile` 使用与 Condition 块相同的引擎评估条件表达式。
3. **激活子块** -- 与循环内部起始连接点相连的块会放入活动执行路径。
4. **收集结果** -- 每次迭代的输出会聚合到 `loop.results`。
5. **递增并重复** -- 计数器递增，然后再次运行步骤 2。循环结束时，会激活连接到循环出口的块。

## 迭代变量

循环体中可使用以下变量：

| 变量 | 类型 | 描述 |
|---|---|---|
| `loop.index` | number | 当前迭代从零开始的索引 |
| `loop.currentItem` | any | 当前项（ForEach）或循环上下文（While） |
| `loop.items` | array/object | 正在迭代的完整集合（仅限 ForEach） |

循环完成后，下游块可以访问：

| 变量 | 类型 | 描述 |
|---|---|---|
| `loop.results` | array | 包含所有迭代输出的有序数组 |

## 配置

| 参数 | 适用于 | 描述 |
|---|---|---|
| **Loop Type** | All | `for`、`forEach`、`while` 或 `doWhile` |
| **Iterations** | For | 重复次数（默认值：5） |
| **Collection** | ForEach | 要迭代的数组或对象。支持 JSON 字面量、`<block.output>` 引用和表达式。 |
| **Condition** | While / Do-While | 每次迭代时评估的布尔表达式（例如 `<variable.i> < 10`） |

## 使用示例

### 处理 API 结果

1. API 块获取客户记录列表。
2. ForEach 循环遍历每位客户。
3. 在循环中，Agent 分析客户数据，Function 存储结果。
4. 循环结束后，Response 块返回聚合后的 `loop.results`。

### 迭代优化

1. 设置为 5 次迭代的 For 循环生成内容变体。
2. 在循环中，Agent 生成草稿，Evaluator 对草稿评分。
3. 循环结束后，Function 从 `loop.results` 中选择得分最高的变体。

## 限制

<Callout type="warning">
  容器块（Loop 和 Parallel）**不能相互嵌套**。不能在 Loop 中放置另一个 Loop，也不能在 Loop 中放置 Parallel。如果需要多维迭代，请重构 workflow，使用顺序循环或分阶段处理数据。
</Callout>

<Callout type="info">
  Loop 会**顺序**执行迭代。要并发执行相互独立的任务，请改用 Parallel 块。
</Callout>

## 最佳实践

- **设置合理的迭代次数**，避免 workflow 长时间运行。默认值为 5。
- **对集合使用 ForEach** -- 它会自动匹配集合长度，并提供 `currentItem`。
- **始终更新条件变量**。在 While 或 Do-While 循环中，如果忘记更改条件所依赖的变量，将导致无限循环（仅受 workflow 超时限制）。
