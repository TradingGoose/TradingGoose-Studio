## 工作原理

条件区块通过顺序评估流程运行：

1. **评估表达式** - 使用当前工作流数据处理 JavaScript/TypeScript 布尔表达式
2. **确定结果** - 根据表达式评估返回 true 或 false
3. **路由工作流** - 根据结果将执行定向到适当的目标区块
4. **提供上下文** - 生成关于该决策的元数据，用于调试和监控

## 配置选项

### 条件

定义一个或多个将被评估的条件。每个条件包括：

- **表达式**：一个评估为 true 或 false 的 JavaScript/TypeScript 表达式
- **路径**：如果条件为 true，则路由到的目标块
- **描述**：对条件检查内容的可选说明

你可以创建多个按顺序评估的条件，第一个匹配的条件将决定执行路径。

### 条件表达式格式

条件使用 JavaScript 语法，可以引用前序块的输入值。

### 访问结果

条件评估后，你可以访问其输出：

- **`<condition.result>`**：条件评估的布尔结果
- **`<condition.matched_condition>`**：匹配到的条件 ID
- **`<condition.content>`**：评估结果的描述
- **`<condition.path>`**：所选路由目标的详细信息

## 高级功能

### 复杂表达式

在条件中使用 JavaScript 运算符和函数：

```javascript
// String operations
<user.email>.endsWith('@company.com')

// Array operations
<api.tags>.includes('urgent')

// Mathematical operations
<agent.confidence> * 100 > 85

// Date comparisons
new Date(<api.created_at>) > new Date('2024-01-01')
```

### 多条件评估

条件按顺序评估，直到有一个匹配：

```javascript
// Condition 1: Check for high priority
<ticket.priority> === 'high'

// Condition 2: Check for urgent keywords
<ticket.subject>.toLowerCase().includes('urgent')

// Condition 3: Default fallback
true
```

### 错误处理

条件会自动处理：
- 未定义或 null 值，进行安全求值
- 类型不匹配，采用适当的回退
- 无效表达式，记录错误日志
- 缺失变量，使用默认值

## 最佳实践

- **正确排列条件顺序**：将更具体的条件放在更通用的条件之前，确保具体逻辑优先于回退逻辑
- **包含默认条件**：添加一个兜底条件（`true`）作为最后一个条件，以处理未匹配的情况，防止工作流执行卡住
- **保持表达式简洁**：使用清晰、直接的布尔表达式，以提高可读性并便于调试
- **为条件添加说明**：添加描述，说明每个条件的用途，以便更好地进行团队协作和维护
- **测试边界情况**：通过使用条件范围边缘的值进行测试，验证条件能否正确处理边界值
