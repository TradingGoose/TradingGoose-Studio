Human in the Loop 模块会暂停正在运行的工作流，等待人员审核、提供输入或批准后再继续。它是为自动化流程添加人工监督的主要机制。

## 概述

<Steps>
  <Step><strong>暂停执行</strong>：工作流在此模块停止并进入等待状态。</Step>
  <Step><strong>显示上下文</strong>：向审核人显示结构化数据，以便其作出知情决定。</Step>
  <Step><strong>通知审批人</strong>：可选择发送包含审核 URL 的 Slack 消息、电子邮件或其他通知。</Step>
  <Step><strong>收集输入并恢复</strong>：审批人填写恢复表单，工作流继续执行，其输入可供下游使用。</Step>
</Steps>

## 工作原理

执行器到达此模块时会：

1. **呈现显示数据** -- 计算 `builderData` 字段，包括 `<variable.name>` 引用，并向审核人显示结构化摘要。
2. **生成恢复 URL** -- 创建唯一 URL 和 API endpoint。URL 打开审核界面；endpoint 接受 `POST` 以编程方式恢复。
3. **发送通知** -- 如果配置了通知 tool，则自动发送恢复 URL。
4. **等待** -- 暂停执行。在审核人操作前，不运行任何下游模块。
5. **恢复** -- 审核人提交表单后继续执行，其填写的字段可作为模块输出。

<Callout type="info">暂停后模块输出 **url**（审核界面链接）和 **resumeEndpoint**（可通过 `curl` 或 HTTP 客户端调用的恢复 API URL）。</Callout>

### 字段

| 字段 | 用途 |
|---|---|
| **Display Data** | 向审核人显示的结构化键值数据。用 `<block.output>` 引用上游变量。 |
| **Notification** | 模块暂停时触发的 tool，用于向相关人员发送恢复 URL。 |
| **Resume Form** | 审批人在恢复前必须填写的字段，这些字段会成为模块输出。 |

## 输出

| 输出 | 类型 | 说明 |
|---|---|---|
| `url` | string | 审批人进行操作的审核界面 URL。 |
| `resumeEndpoint` | string | 通过 HTTP POST 恢复工作流的 API endpoint。 |

## 最佳实践

- **始终配置通知**，让审批人知道工作流正在等待。否则必须手动共享恢复 URL。
- **保持显示数据聚焦** -- 只包含审核人作出决定所需的信息。
- **谨慎设计恢复表单** -- 下游模块将依赖这里定义的字段，因此应使用清晰名称。
