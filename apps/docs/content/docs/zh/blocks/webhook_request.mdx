Webhook 请求块会向外部 webhook URL 发送**出站** HTTP POST 请求。可用于将工作流结果推送到第三方服务，例如 Zapier、Make、n8n，或任何接受 webhook 载荷的自定义端点。

<Callout type="warning">
  此块发送**出站** webhook 调用（你的工作流调用外部 URL）。它与**Webhook 触发器**不同，后者用于监听启动工作流的**入站**请求。
</Callout>

## 概览

<Steps>
  <Step>
    <strong>设置目标 URL</strong>：指向任何接受 HTTP POST 请求的端点
  </Step>
  <Step>
    <strong>构建 JSON 载荷</strong>：使用 `<agent.content>` 等变量引用引入上游块的数据
  </Step>
  <Step>
    <strong>可选地签署请求</strong>：提供 HMAC-SHA256 签名密钥，以便接收方验证真实性
  </Step>
  <Step>
    <strong>添加自定义请求头</strong>：包含 API 密钥、内容类型，或接收方需要的任何额外请求头
  </Step>
</Steps>

## 工作原理

当该块执行时，它会：

1. 解析 URL、载荷和请求头中诸如 `<agent.content>` 这类精确的源限定引用，以及 `<variable.userId>` 这类工作流变量。不要臆造通用的块前缀占位符。
2. 将载荷序列化为 JSON。
3. 如果提供了**签名密钥**，则对载荷计算 HMAC-SHA256 签名，并将其作为 webhook 请求头附加，以便接收服务器验证请求未被篡改。
4. 使用 `Content-Type: application/json` 以及你配置的任何额外请求头发送 POST 请求。
5. 将响应数据、状态码和响应头作为块的输出返回。

### 字段

| 字段 | 必填 | 描述 |
|---|---|---|
| **Webhook URL** | 是 | 目标端点。必须接受 HTTP POST 请求。 |
| **负载** | 否 | 要发送的 JSON 正文。使用精确的源限定标签，例如 `<agent.content>`，或工作流变量，例如 `<variable.userId>`。 |
| **签名密钥** | 否 | 用于生成 HMAC-SHA256 签名头以验证负载的共享密钥。 |
| **附加请求头** | 否 | 附加到请求的键值对（例如 `Authorization: Bearer ...`）。 |

## 输出

| 输出 | 类型 | 描述 |
|---|---|---|
| `data` | json | 来自外部端点的已解析响应正文 |
| `status` | number | 端点返回的 HTTP 状态码 |
| `headers` | json | 响应头 |

## 最佳实践

- **将密钥存储在环境变量中** -- 使用 `{{WEBHOOK_SECRET}}` 引用你的签名密钥，而不是直接粘贴。
- **检查状态输出** -- 在 webhook 之后使用条件或路由块来妥善处理非 2xx 响应。
- **保持负载小** -- 只发送接收方需要的数据。大型负载会增加延迟，并且可能被某些端点拒绝。
