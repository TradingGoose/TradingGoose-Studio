记忆块用于存储和检索在多次工作流执行之间持久保留的对话消息。它设计为与 Agent 块配合使用，为你的 Agent 提供跨运行存续的长期对话上下文。

## 概览

<Steps>
  <Step>
    <strong>添加记忆</strong>：存储一条带角色（user、assistant 或 system）的消息，并归入指定的记忆 ID
  </Step>
  <Step>
    <strong>获取记忆</strong>：按 ID 检索单条记忆条目
  </Step>
  <Step>
    <strong>获取全部记忆</strong>：获取当前工作流存储的所有记忆
  </Step>
  <Step>
    <strong>删除记忆</strong>：按 ID 删除记忆条目
  </Step>
</Steps>

## 工作原理

记忆条目以聊天风格的消息存储，包含三个必填字段：用于限定记忆范围的 **ID**、**Role**（`user`、`assistant` 或 `system`）以及 **Content** 文本。之后检索记忆并将其传入 Agent 块的 Memories 输入时，Agent 会将它们视为先前的对话轮次——从而支持跨独立执行的多轮对话。

典型的对话工作流会在一个 Agent 周围使用三个记忆块：

1. **记忆（添加，角色：user）** —— 在 Agent 运行前保存传入的用户消息
2. **Agent** —— 将消息与检索到的记忆作为上下文进行处理
3. **记忆（添加，角色：assistant）** —— 在 Agent 运行后保存其响应

<Callout type="info">
  记忆 ID 用于限定对话范围。在多次执行中使用同一 ID 可构建连续的对话历史，或使用不同 ID 来维护独立线程。
</Callout>

## 输出

| 输出 | 类型 | 说明 |
|---|---|---|
| `memories` | json | 检索到的记忆数据（消息数组） |
| `id` | string | 被操作的记忆标识符 |

## 最佳实践

- **使用一致的 ID** -- 记忆 ID 是将消息分组为对话的键。使用稳定的标识符（例如用户 ID 或会话 ID），以便记忆在多次运行中正确累积。
- **存储对话的双方** -- 在 Agent 之前添加一条 `user` 角色的消息，并在其后添加一条 `assistant` 角色的消息，以便保留完整的对话。
- **需要时清理** -- 使用删除操作清除陈旧的对话，并防止记忆无限增长。
