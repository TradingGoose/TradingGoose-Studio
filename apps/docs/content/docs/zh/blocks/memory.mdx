Memory 块用于存储和检索可跨 workflow 执行保留的对话消息。它与 Agent 块配合使用，为代理提供可在多次运行之间保留的长期对话上下文。

## 概述

<Steps>
  <Step>
    <strong>Add Memory</strong>：使用指定角色（user、assistant 或 system）和记忆 ID 存储消息
  </Step>
  <Step>
    <strong>Get Memory</strong>：按 ID 检索单个记忆条目
  </Step>
  <Step>
<strong>获取所有记忆</strong>：获取当前工作流存储的所有记忆
  </Step>
  <Step>
    <strong>Delete Memory</strong>：按 ID 删除记忆条目
  </Step>
</Steps>

## 工作原理

记忆条目以聊天消息形式存储，包含三个必填字段：用于限定记忆的 **ID**、**Role**（`user`、`assistant` 或 `system`）和 **Content** 文本。检索记忆并将其传入 Agent 块的 Memories 输入后，代理会将其视为先前的对话轮次，从而在独立执行之间保持多轮对话。

典型的对话 workflow 会在 Agent 前后使用三个 Memory 块：

1. **Memory (Add, role: user)** -- 在运行 Agent 前保存传入的用户消息
2. **Agent** -- 使用检索到的记忆作为上下文处理消息
3. **Memory (Add, role: assistant)** -- 在运行 Agent 后保存其响应

<Callout type="info">
  记忆 ID 用于限定对话。在多次执行中使用同一 ID 可创建连续的对话历史记录；使用不同 ID 可维护独立线程。
</Callout>

## 操作

<Tabs items={['Add Memory', 'Get Memory', 'Get All Memories', 'Delete Memory']}>
  <Tab>
    在记忆存储中保存新消息。

    | 字段 | 必填 | 描述 |
    |---|---|---|
    | **ID** | 是 | 将消息分组到对话中的记忆标识符 |
    | **Role** | 是 | `user`、`assistant` 或 `system` |
    | **Content** | 是 | 要存储的消息文本 |
  </Tab>
  <Tab>
    检索指定记忆 ID 下存储的所有消息。

    | 字段 | 必填 | 描述 |
    |---|---|---|
    | **ID** | 是 | 要检索的记忆标识符 |
  </Tab>
  <Tab>
    返回当前 workflow 的所有记忆条目。无需其他字段。
  </Tab>
  <Tab>
    按 ID 删除记忆条目。

    | 字段 | 必填 | 描述 |
    |---|---|---|
    | **ID** | 是 | 要删除的记忆标识符 |
  </Tab>
</Tabs>

## 输出

| 输出 | 类型 | 描述 |
|---|---|---|
| `memories` | json | 检索到的记忆数据（消息数组） |
| `id` | string | 本次操作使用的记忆标识符 |

## 最佳实践

- **使用一致的 ID** -- 记忆 ID 是将消息组合成对话的键。使用稳定标识符（例如用户 ID 或会话 ID），确保记忆在多次运行之间正确累积。
- **保存对话双方** -- 在 Agent 运行前添加 `user` 角色消息，并在运行后添加 `assistant` 角色消息，以保留完整对话。
- **按需清理** -- 使用 Delete 操作清除过时对话，避免记忆无限增长。
