## 安装

```bash
npm install tradinggoose-ts-sdk
```

## 执行工作流

```typescript
import { TradingGooseClient } from 'tradinggoose-ts-sdk'

const client = new TradingGooseClient({
  apiKey: process.env.TRADINGGOOSE_API_KEY!,
  baseUrl: 'https://tradinggoose.ai',
})

const result = await client.executeWorkflow('workflow-id', {
  input: { message: 'Analyze this' },
  timeout: 30000,
  stream: true,
  selectedOutputs: ['agent1.content'],
})
```

`ExecutionOptions` 包含 `input`、`timeout`（毫秒，默认值为 `30000`）、`stream` 和 `selectedOutputs`。流式字段是请求控制项；当前 SDK 返回 `WorkflowExecutionResult`，而不是 SSE 迭代器。

## 状态和验证

- `getWorkflowStatus(workflowId)` 返回 `WorkflowStatus`。
- `validateWorkflow(workflowId)` 返回工作流是否已部署。
- `setApiKey(apiKey)` 和 `setBaseUrl(baseUrl)` 用于更新客户端配置。

## 重试和限制

`executeWithRetry(workflowId, options, retryOptions)` 仅重试 `RATE_LIMIT_EXCEEDED`。`RetryOptions` 的默认值为 `maxRetries: 3`、`initialDelay: 1000` ms、`maxDelay: 30000` ms 和 `backoffMultiplier: 2`。客户端遵循 `Retry-After` 并应用 ±25% 的抖动。

- `getRateLimitInfo(): RateLimitInfo | null` 公开以毫秒为单位的 `limit`、`remaining`、`reset` 和可选的 `retryAfter`。
- `getUsageLimits(): Promise<UsageLimits>` 公开同步和异步的 `isLimited`、`limit`、`remaining` 和 `resetAt`，以及 `authType` 和用量字段 `currentPeriodCost`、`limit` 与 `plan`。

## 错误和结果

`TradingGooseError` 保留 API `code` 和 HTTP `status`。客户端在自身的失败路径中使用 `TIMEOUT`、`EXECUTION_ERROR`、`STATUS_ERROR`、`RATE_LIMIT_EXCEEDED` 和 `USAGE_ERROR`。成功执行会返回 `WorkflowExecutionResult`，其中包含 `success`，以及可选的输出、错误、日志、元数据、追踪跨度和持续时间。

完整示例和文件上传行为请参阅 [TypeScript SDK 软件包 README](https://github.com/TradingGoose/TradingGoose-Studio/blob/staging/packages/ts-sdk/README.md)。
