## 安装

```bash
pip install tradinggoose-sdk
```

## 执行工作流

```python
import os
from tradinggoose import TradingGooseClient

client = TradingGooseClient(
    api_key=os.environ["TRADINGGOOSE_API_KEY"],
    base_url="https://tradinggoose.ai",
)

result = client.execute_workflow(
    "workflow-id",
    input_data={"message": "Analyze this"},
    timeout=30.0,
    stream=True,
    selected_outputs=["agent1.content"],
)
```

`timeout` 以秒为单位，默认值为 `30.0`。`stream` 和 `selected_outputs` 是请求控制项；当前 SDK 返回 `WorkflowExecutionResult`，而不是流式迭代器。

## 状态和验证

- `get_workflow_status(workflow_id)` 返回 `WorkflowStatus`。
- `validate_workflow(workflow_id)` 返回工作流是否已部署。
- `set_api_key(api_key)`、`set_base_url(base_url)` 和 `close()` 用于管理客户端。
- 客户端支持通过 `with TradingGooseClient(...) as client` 进行上下文管理。

## 重试和限制

`execute_with_retry` 仅重试 `RATE_LIMIT_EXCEEDED`。默认值为 `max_retries=3`、`initial_delay=1.0` 秒、`max_delay=30.0` 秒和 `backoff_multiplier=2.0`。它遵循 `Retry-After` 并应用 ±25% 的抖动。Python 将这些值公开为关键字参数，而不是单独的重试选项类型。

- `get_rate_limit_info()` 返回 `RateLimitInfo` 或 `None`，其中 `limit`、`remaining`、`reset` 和可选的 `retry_after` 以毫秒存储。
- `get_usage_limits()` 返回 `UsageLimits(success, rate_limit, usage)`；速率限制和用量的有效负载是与 API 响应匹配的字典。

## 错误和结果

`TradingGooseError` 保留 API `code` 和 HTTP `status`。客户端在自身的失败路径中使用 `TIMEOUT`、`EXECUTION_ERROR`、`STATUS_ERROR`、`RATE_LIMIT_EXCEEDED` 和 `USAGE_ERROR`。`WorkflowExecutionResult` 包含 `success`，以及可选的输出、错误、日志、元数据、追踪跨度和持续时间。

完整示例和文件上传行为请参阅 [Python SDK 软件包 README](https://github.com/TradingGoose/TradingGoose-Studio/blob/staging/packages/python-sdk/README.md)。
