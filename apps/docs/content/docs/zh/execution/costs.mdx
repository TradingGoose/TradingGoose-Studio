TradingGoose 根据配置的执行费用和任何按量计费的模型使用量来计算工作流费用。这两个数值都可以根据工作区所配置的用户或组织账单负责人的生效层级进行调整。

## 费用如何计算

当计费启用时，工作流可以有两个费用构成：

- **执行费用**：实例配置的工作流费用乘以当前层级的工作流执行乘数。
- **AI 模型使用量**：每个执行跨度记录的提供商模型费用乘以当前层级的工作流模型费用乘数。

```javascript
executionCost = configuredWorkflowCharge * tierWorkflowExecutionMultiplier
adjustedModelCost = recordedModelCost * tierWorkflowModelCostMultiplier
totalCost = executionCost + sum(adjustedModelCost)
```

<Callout type="info">
  当计费被禁用时，执行费用为零，记录的模型费用按乘数 1 计算。费用和乘数应以计费层级配置为准，而不是本指南中的固定值。
</Callout>

## 日志中的模型明细

对于使用 AI 模块的工作流，你可以在日志中查看详细的费用信息：

日志详情侧边栏包含一个模型明细部分，显示：
- **Token 使用量**：每个模型的输入和输出 token 数量
- **费用明细**：每个模型的输入、输出和总费用
- **使用的模型**：哪些模型计入了执行费用
- **总费用**：整个工作流执行的汇总费用

## 价格与限制

可用的计费层级和模型目录由 TradingGoose 部署配置，并且可能独立于本文档发生变化。使用 **设置 → 订阅** 查看当前用量、用量限制以及可用的计划、价格和宣传功能。下方的用量限制 API 报告已认证用户的个人计费范围的速率、存储、保留和乘数数值；它不会确定组织针对工作区的生效层级。使用 Agent 模块的模型选择器查看当前可供工作区使用的模型。

如果你收到私有层级的访问码，请在**设置 → 订阅**中输入。访问码区分大小写，但会忽略首尾空白字符。有效的访问码会让对应的私有方案对你的用户可用。

计费层级还可以限制每个排队中工作流执行的最长时长。达到该上限的执行会被终止，并以错误 `Workflow execution time limit exceeded` 记录。

## 成本优化策略

<Accordions>
  <Accordion title="模型选择">
    选择与任务复杂度相匹配的模型，并在部署前查看其当前的服务商价格。
  </Accordion>

  <Accordion title="提示工程">
    结构良好、简洁的提示词可减少 token 用量，同时不牺牲质量。
  </Accordion>

  <Accordion title="本地模型">
    适合使用本地模型时，请使用 Ollama，以避免外部模型服务商的费用。工作流执行费用仍可能产生。
  </Accordion>

  <Accordion title="缓存与复用">
    在一次运行中复用上游输出或工作流变量，而不是重复调用 AI 模型。
  </Accordion>

  <Accordion title="批量处理">
    在一次 AI 请求中处理多个条目，而不是逐个调用。
  </Accordion>
</Accordions>

## 用量监控

在设置 → 订阅中监控你的用量和账单：

- **当前用量**：当前周期内累计的用量与费用
- **用量上限**：有效的支出限额及已消耗百分比
- **方案管理**：启用账单后可用的订阅操作

### 以编程方式跟踪个人用量

你可以使用 API 以编程方式查询已认证用户的个人用量和限额：

**端点：**

```text
GET /api/users/me/usage-limits
```

**身份验证：**
- 在 `X-API-Key` 请求头中包含你的 API 密钥

**示例请求：**

```bash
curl -X GET -H "X-API-Key: YOUR_API_KEY" -H "Content-Type: application/json" https://www.tradinggoose.ai/api/users/me/usage-limits
```

**示例响应：**

```jsonc
{
  "success": true,
  "rateLimit": {
    "sync": { "isLimited": false, "limit": 10, "remaining": 10, "resetAt": "2025-09-08T22:51:55.999Z" },
    "async": { "isLimited": false, "limit": 50, "remaining": 50, "resetAt": "2025-09-08T22:51:56.155Z" },
    "authType": "api"
  },
  "usage": {
    "currentPeriodCost": 12.34,
    "limit": 100,
    "tier": {
      "id": "tier_example",
      "displayName": "Example Tier",
      "ownerType": "user",
      "usageScope": "individual",
      "syncRateLimitPerMinute": 10,
      "asyncRateLimitPerMinute": 50,
      "apiEndpointRateLimitPerMinute": 60,
      "logRetentionDays": 30,
      "workflowExecutionMultiplier": 1,
      "workflowModelCostMultiplier": 1
      // The response includes the remaining BillingTierSummary fields.
    }
  },
  "storage": {
    "usedBytes": 5242880,
    "limitBytes": 1073741824,
    "percentUsed": 0.48828125
  }
}
```

**响应字段：**
- `currentPeriodCost` 反映当前账单周期的用量
- `limit` 是已认证用户账单范围内的有效用量上限
- `tier` 是完整的计费层级摘要，包括其配置的速率限制、数据保留和成本倍率
- `storage` 报告当前字节用量、字节上限和已用百分比

示例值仅供参考。请以您账户返回的响应为准，不要依赖固定的套餐名称或限制。

## 成本管理最佳实践

1. **定期监控**：经常检查您的使用情况仪表板，以避免意外
2. **设置预算**：在您的套餐允许的情况下，将可编辑的使用限额用作支出护栏
3. **优化工作流**：检查高成本执行，并优化提示或模型选择
4. **使用合适的模型**：根据任务需求匹配模型复杂度
5. **批量处理相似任务**：尽可能合并多个请求以减少开销
