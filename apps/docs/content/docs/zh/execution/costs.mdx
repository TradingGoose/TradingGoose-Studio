TradingGoose 为工作区原始的用户或组织账单负责人记录已接受的产品费用。共享财务策略在执行和恢复过程中保留原始操作者、计费周期和报价。

## 实际计入的费用

- **工作流执行**：使用原始报价保存的基础费用和层级执行倍率。同一次逻辑执行只结算一次基础费用，子工作流单独结算。
- **Function 和自定义工具运行**：使用已保存的每秒费用和 Function 倍率，乘以实际运行毫秒数再除以 1000。已接触运行环境的尝试即使代码失败，也可能产生这项费用。
- **模型和嵌入工作**：每个实际步骤或批次都需要财务准入和已验证的接受结果。当前集成无法提供通用原生模型的美元费用。Token 数量不能证明美元费用，缺少提供商价格也不会被视为已知的零费用。

金额、限额、额度、倍率和收据均使用精确的十进制字符串。Function 费用保留完整的小数精度，不进行六位小数量化。金额显示可以为便于阅读而四舍五入。开票时按已规定的半入规则将美元转换为美分；此转换不会改写底层用量账本。

完成要求已验证的财务接受结果和经过授权的规范输出读取。即使工作已经完成，财务或读取失败也可能阻止成功交付；这不允许重复执行该工作。恢复使用原始财务身份和已接受的操作，不会重复收取同一项已完成工作的费用。人工审核检查点也保留这一身份。

<Callout type="info">
  计费事实以实际接受的用量和已保存的执行报价为准。配置并验证的零费用与无法提供的模型美元费用不同。修改配置不会改写现有报价、原始付款方或原始周期。
</Callout>

## 活跃用量与重新加载的日志

活跃请求的原生结果可能包含可选的输入、输出或总 token 数量以及所选模型。缺失的计数仍不可用。通用美元费用标记为不可用，不使用手动价格表或基于 token 的估算填补。

重新加载 Records 时，通过经过授权的规范存储保留功能性的输入、输出、工具和工作流执行详情。提供商诊断、模型费用报告和每轮 token 总量不是持久的产品报告。重新加载不会根据追踪或对话大小重建模型费用明细。请在**设置 → 订阅**中查看当前周期实际计入的用量；可见的模型小计不等于财务账本。

## 价格与限制

可用的计费层级和模型目录由 TradingGoose 部署配置，并且可能独立于本文档发生变化。使用 **设置 → 订阅** 查看当前用量、用量限制以及可用的计划、价格和宣传功能。下方的用量限制 API 报告已认证用户的个人计费范围的速率、存储、保留和乘数数值；它不会确定组织针对工作区的生效层级。使用 Agent 模块的模型选择器查看当前可供工作区使用的模型。

如果你收到私有层级的访问码，请在**设置 → 订阅**中输入。访问码区分大小写，但会忽略首尾空白字符。有效的访问码会让对应的私有方案对你的用户可用。

计费层级还可以限制每个排队中工作流执行的最长时长。达到该上限的执行会被终止，并以错误 `Workflow execution time limit exceeded` 记录。

## 用量监控

在设置 → 订阅中监控你的用量和账单：

- **当前用量**：当前周期内累计的用量与费用
- **用量上限**：有效的支出限额及已消耗百分比
- **方案管理**：启用账单后可用的订阅操作

### 以编程方式跟踪个人用量

你可以使用 API 以编程方式查询已认证用户的个人用量和限额：

**端点：**

```text
GET /api/users/me/usage-limits
```

**身份验证：**
- 在 `X-API-Key` 请求头中包含你的 API 密钥

**示例请求：**

```bash
curl -X GET -H "X-API-Key: YOUR_API_KEY" -H "Content-Type: application/json" https://www.tradinggoose.ai/api/users/me/usage-limits
```

**示例响应：**

**金额 ABI 不兼容变更：** `currentPeriodCost` 是精确的美元十进制字符串，例如 `"9007199254740993.30000000000000001"`；金额用量 `limit` 是十进制字符串，无上限时为 `null`。计费层级的价格、额度和倍率也保留为十进制字符串或配置的 `null`。请保留原值，不要转换为 `Number`/`float`。速率计数、席位和存储字段仍为数值。

```jsonc
{
  "success": true,
  "rateLimit": {
    "sync": { "isLimited": false, "limit": 10, "remaining": 10, "resetAt": "2025-09-08T22:51:55.999Z" },
    "async": { "isLimited": false, "limit": 50, "remaining": 50, "resetAt": "2025-09-08T22:51:56.155Z" },
    "authType": "api"
  },
  "usage": {
    "currentPeriodCost": "12.34",
    "limit": "100",
    "tier": {
      "id": "tier_example",
      "displayName": "Example Tier",
      "ownerType": "user",
      "usageScope": "individual",
      "syncRateLimitPerMinute": 10,
      "asyncRateLimitPerMinute": 50,
      "apiEndpointRateLimitPerMinute": 60,
      "logRetentionDays": 30,
      "workflowExecutionMultiplier": "1",
      "workflowModelCostMultiplier": "1"
      // The response includes the remaining BillingTierSummary fields.
    }
  },
  "storage": {
    "usedBytes": 5242880,
    "limitBytes": 1073741824,
    "percentUsed": 0.48828125
  }
}
```

**响应字段：**
- `currentPeriodCost` 反映当前账单周期的用量
- `limit` 是已认证用户账单范围内的有效用量上限
- `tier` 是完整的计费层级摘要，包括其配置的速率限制、数据保留和成本倍率
- `storage` 报告当前字节用量、字节上限和已用百分比

示例值仅供参考。请以您账户返回的响应为准，不要依赖固定的套餐名称或限制。

## 成本管理最佳实践

1. **定期监控**：经常检查您的使用情况仪表板，以避免意外
2. **设置预算**：在您的套餐允许的情况下，将可编辑的使用限额用作支出护栏
3. **优化工作流**：检查高成本执行，并优化提示或模型选择
4. **使用合适的模型**：根据任务需求匹配模型复杂度
5. **批量处理相似任务**：尽可能合并多个请求以减少开销
