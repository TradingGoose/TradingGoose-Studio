TradingGoose 为所有工作流执行提供全面的日志记录，让你完整掌握工作流的运行方式、流经的数据以及可能出现问题的地方。

## 日志系统

TradingGoose 提供两种互补的日志界面，以适配不同的工作流和使用场景：

### 实时控制台

在手动执行或工作区对话执行期间，日志会显示在配置为同一工作流的 [工作流控制台](/widgets/workflow-console) 组件中。你可以将该组件放置在仪表盘布局中的任意位置，并调整其大小。

控制台会显示：
- 块执行进度，并高亮当前正在执行的块
- 块完成时的实时输出
- 每个块的执行耗时
- 成功/错误状态指示

### 日志页面

所有工作流执行——无论是手动触发，还是通过 API、Chat、Schedule 或 Webhook 触发——都会记录到专用的日志页面：

日志页面提供：
- 按时间范围、状态、触发类型、文件夹和工作流进行全面的筛选
- 跨所有日志的搜索功能
- 用于实时更新的实时模式
- 日志保留时长取决于工作区所配置用户或组织计费主体当前生效的套餐等级

## 日志详情侧边栏

点击任意日志条目，会打开详细的侧边栏视图，展示执行时间线、块级详情和成本摘要。

### 块输入/输出

通过标签页查看每个块完整的数据流，可在以下内容之间切换：

<Tabs items={['输出', '输入']}>
  <Tab>
    **输出标签页**展示块的执行结果：
    - 带 JSON 格式的结构化数据
    - 针对 AI 生成内容的 Markdown 渲染
    - 便于提取数据的复制按钮
  </Tab>
  
  <Tab>
    **输入标签页**显示传递给块的内容：
    - 已解析的变量值
    - 其他块引用的输出
    - 使用的环境变量
    - 凭据形态的值会在冻结的工作流快照中被脱敏；其他记录在案的工具参数和输出仍应视为可能敏感
  </Tab>
</Tabs>

### 执行时间线

对于工作流级别的日志，查看详细的执行指标：
- 开始和结束时间戳
- 总工作流持续时间
- 各个区块的执行时间
- 性能瓶颈识别

## 工作流快照

对于任何已记录的执行，点击“查看快照”以查看执行时的确切工作流状态。快照提供：
- 显示工作流结构的冻结画布
- 执行期间的区块状态和连接
- 点击任何区块以查看其输入和输出
- 用于调试此后已被修改的工作流

<Callout type="info">
  如果存储的工作流快照不可用，快照视图将显示“未找到记录状态”消息。
</Callout>

## 日志保留

日志保留由工作区账单负责人的有效层级配置。有限的 `logRetentionDays` 值决定何时删除旧日志；没有保留限制的层级会无限期保留日志。请检查当前的订阅设置，而不是依赖固定的套餐名称或持续时间。

## 最佳实践

### 开发阶段
- 在测试期间使用实时控制台获取即时反馈
- 检查区块输入和输出以验证数据流
- 使用工作流快照比较正常版本与故障版本

### 生产环境
- 定期监控日志页面以发现错误或性能问题
- 设置过滤器以关注特定的工作流或时间段
- 在关键部署期间使用实时模式实时观看执行

### 调试阶段
- 始终检查执行时间线以识别缓慢的区块
- 比较正常执行与失败执行之间的输入
- 使用工作流快照查看问题发生时的确切状态
