TradingGoose supports two complementary variable systems. **Environment variables** store configuration values and secrets (API keys, tokens, database URLs) that stay outside your workflow definitions and are resolved at execution time. **Workflow variables** hold shared state within a run: define their initial values in the Variables panel, reference them from blocks, and update them with a Variables block.

Together they cover both external configuration and internal data flow. Environment variables keep secrets safe and portable across workflows, while workflow variables let blocks pass data to each other without direct connections.

## Variable Types

<Cards>
  <Card title="Environment Variables" href="/variables/environment-variables">
    Manage API keys, tokens, and other secrets at the personal or workspace level. Referenced with double-brace syntax and resolved when a workflow runs.
  </Card>
  <Card title="Workflow Variables" href="/variables/workflow-variables">
    Shared values scoped to one workflow execution. Define initial values in the Variables panel and use a Variables block for runtime assignments.
  </Card>

## Quick Comparison

| | Environment Variables | Workflow Variables |
|---|---|---|
| **Scope** | Personal or workspace-wide | Single workflow |
| **Lifetime** | Persistent across all runs | Runtime changes last only for the current run; new runs load saved initial values |
| **Typical use** | API keys, tokens, config | Passing data between blocks, state |
| **Access syntax** | `{{VARIABLE_NAME}}` | `<variable.name>` via dropdown |
| **Where to edit** | Environment page (permissions apply) | Workflow Variables panel/widget; Variables block for runtime changes |
