TradingGoose records accepted product charges for the workspace's original user or organization billing owner. The shared financial policy preserves the original actor, billing period and pricing quote throughout execution and resume.

## Applied Charges

- **Workflow execution** uses the configured base charge and tier execution multiplier captured in the original quote. The same logical execution settles its base charge once. Child workflows settle independently.
- **Function and custom-tool runtime** uses the captured per-second charge and tier Function multiplier multiplied by actual runtime milliseconds divided by 1000. A contacted runtime attempt can incur this charge even when its code fails.
- **Model and embedding work** requires financial admission and verified acceptance for each actual step or batch. Generic native model USD is unavailable in the current integration. Token counts do not establish a dollar charge, and missing provider prices are never treated as known zero.

Amounts, limits, allowances, multipliers and receipts use exact decimal strings. Function charges retain their full decimal precision; there is no six-decimal quantization. Currency display can round for readability. The invoice boundary converts USD to cents using the documented half-up rule; that conversion does not change the underlying usage ledger.

Completion requires verified financial acceptance and authorized canonical output readback. A financial or readback failure can prevent successful delivery after work has finished; it does not authorize repeating that work. Resume reuses the original financial identity and accepted occurrences rather than charging the same completed work again. A human review checkpoint preserves that identity.

<Callout type="info">
  Read actual accepted usage and the execution's captured quote for billing facts. A configured, verified zero charge differs from unavailable model USD. Changing billing configuration does not rewrite an existing quote, original payer or original period.
</Callout>

## Active Usage and Reloaded Logs

During an active request, native results can expose optional input, output or total token counts and the selected model. Missing counters remain unavailable. Generic USD is labelled unavailable; no manual price table or token-based estimate fills the gap.

Reloaded Records retain functional inputs, outputs, tools and workflow execution details through authorized canonical storage. Provider diagnostics, model cost reports and per-turn token totals are not durable product reporting. Reload does not reconstruct a model-cost breakdown from traces or transcript size. Use **Settings → Subscription** for actual applied current-period usage; a visible model subtotal is not the financial ledger.

## Pricing and Limits

The available billing tiers and model catalog are configured by the TradingGoose deployment and can change independently of this documentation. Use **Settings → Subscription** for current usage, the usage limit, and the available plans, prices, and advertised features. The usage-limits API below reports rate, storage, retention, and multiplier values for the authenticated user's personal billing scope; it does not resolve an organization's effective tier for a workspace. Use the Agent block's model selector for the models currently available to your workspace.

If you receive an access code for a private tier, enter it in **Settings → Subscription**. Codes are case-sensitive, although surrounding whitespace is ignored. A valid code makes the corresponding private plan available to your user.

A billing tier can also impose a maximum duration on each queued workflow execution. An execution that reaches that limit is terminated and recorded with the error `Workflow execution time limit exceeded`.

## Usage Monitoring

Monitor your usage and billing in Settings → Subscription:

- **Current Usage**: Usage and costs accumulated in the current period
- **Usage Limit**: The effective spending limit and percentage consumed
- **Plan Management**: Available subscription actions when billing is enabled

### Programmatic Personal Usage Tracking

You can query the authenticated user's personal usage and limits programmatically using the API:

**Endpoint:**
```text
GET /api/users/me/usage-limits
```

**Authentication:**
- Include your API key in the `X-API-Key` header

**Example Request:**
```bash
curl -X GET -H "X-API-Key: YOUR_API_KEY" -H "Content-Type: application/json" https://www.tradinggoose.ai/api/users/me/usage-limits
```

**Example Response:**

**Breaking money ABI:** `currentPeriodCost` is exact USD decimal text, such as `"9007199254740993.30000000000000001"`; the monetary usage `limit` is a decimal string or `null` for unlimited. Nested tier prices, allowances and billing multipliers remain decimal strings or configured `null`. Preserve these values without `Number`/`float` conversion. Rate-limit counts, seats and storage fields remain numeric.

```jsonc
{
  "success": true,
  "rateLimit": {
    "sync": { "isLimited": false, "limit": 10, "remaining": 10, "resetAt": "2025-09-08T22:51:55.999Z" },
    "async": { "isLimited": false, "limit": 50, "remaining": 50, "resetAt": "2025-09-08T22:51:56.155Z" },
    "authType": "api"
  },
  "usage": {
    "currentPeriodCost": "12.34",
    "limit": "100",
    "tier": {
      "id": "tier_example",
      "displayName": "Example Tier",
      "ownerType": "user",
      "usageScope": "individual",
      "syncRateLimitPerMinute": 10,
      "asyncRateLimitPerMinute": 50,
      "apiEndpointRateLimitPerMinute": 60,
      "logRetentionDays": 30,
      "workflowExecutionMultiplier": "1",
      "workflowModelCostMultiplier": "1"
      // The response includes the remaining BillingTierSummary fields.
    }
  },
  "storage": {
    "usedBytes": 5242880,
    "limitBytes": 1073741824,
    "percentUsed": 0.48828125
  }
}
```

**Response Fields:**
- `currentPeriodCost` reflects usage in the current billing period
- `limit` is the effective usage limit for the authenticated user's billing scope
- `tier` is the complete billing-tier summary, including its configured rate limits, retention, and cost multipliers
- `storage` reports the current byte usage, byte limit, and percentage used

The example values are illustrative. Read the response returned for your account instead of relying on fixed plan names or limits.

## Cost Management Best Practices

1. **Monitor Regularly**: Check your usage dashboard frequently to avoid surprises
2. **Set Budgets**: Where your tier permits it, use the editable usage limit as a spending guardrail
3. **Optimize Workflows**: Review high-cost executions and optimize prompts or model selection
4. **Use Appropriate Models**: Match model complexity to task requirements
5. **Batch Similar Tasks**: Combine multiple requests when possible to reduce overhead
