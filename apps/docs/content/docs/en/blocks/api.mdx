## Tools

### `http_request`

Make HTTP requests with comprehensive support for methods, headers, query parameters, path parameters, and form data. Features configurable timeout and status validation for robust API interactions.

#### Input

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `url` | string | Yes | The URL to send the request to |
| `method` | string | No | HTTP method \(GET, POST, PUT, PATCH, DELETE\) |
| `headers` | object | No | HTTP headers to include |
| `body` | object | No | Request body \(for POST, PUT, PATCH\) |
| `params` | object | No | URL query parameters to append |
| `pathParams` | object | No | URL path parameters to replace \(e.g., :id in /users/:id\) |
| `formData` | object | No | Form data to send \(will set appropriate Content-Type\) |
| `timeout` | number | No | Request timeout in milliseconds |
| `validateStatus` | object | No | Custom status validation function |

#### Output

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| `data` | json | Response data from the HTTP request \(JSON object, text, or other format\) |
| `status` | number | HTTP status code of the response \(e.g., 200, 404, 500\) |
| `headers` | object | Response headers as key-value pairs |
| `headers.content-type` | string | Content type of the response |
| `headers.content-length` | string | Content length |

## Input

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `url` | string | Yes | Request URL |
| `method` | string | Yes | HTTP method |
| `headers` | json | No | Request headers |
| `body` | json | No | Request body data |
| `params` | json | No | URL query parameters |

## Output

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| `data` | json | API response data \(JSON, text, or other formats\) |
| `status` | number | HTTP status code \(200, 404, 500, etc.\) |
| `headers` | json | HTTP response headers as key-value pairs |


## Usage Instructions

Send an HTTP request using the configured method, URL, headers, query parameters, and optional body. Standard request headers are added automatically. Reference upstream outputs and workflow variables using their exact TradingGoose tags. Responses expose data, status, and headers. Non-successful requests fail the block; connect an error path for recovery. The block does not automatically retry failed requests.
