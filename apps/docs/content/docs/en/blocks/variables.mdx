The Variables block updates variables already defined in the workflow. Assignments change the current execution's values; they do not save new initial values or persist runtime state between runs.

## Configure assignments

1. Create the variables in the workflow's Variables panel, with names, types, and initial values.
2. Add a Variables block and select each variable to update.
3. Supply a literal value or an exact reference to an upstream output.

For example, after an API block returns a customer profile:

```text
customerEmail = <api.data.email>
userId = <api.data.id>
userTier = <api.data.tier>
```

Use the actual source block's name. In plain-text value fields, enter text without surrounding quotation marks.

## Calculations

The Variables block converts values to the selected variable type; it does not evaluate JavaScript expressions. A numeric assignment such as `<variable.retryCount> + 1` becomes text such as `0 + 1` and fails numeric conversion.

Calculate in a Function block first:

```typescript
return <variable.retryCount> + 1;
```

Then assign `retryCount` to `<function.result>` in the Variables block. Use the same pattern for a loop counter such as `itemsProcessed`.

## Read values and outputs

- Read the latest value anywhere in the run with `<variable.retryCount>` or `<variable.customerEmail>`.
- Block outputs contain the assigned names directly, for example `<variables.retryCount>`. There is no `assignments` wrapper.
- For a retry workflow, connect the failed block's **error path** to your recovery logic. A normal success connection does not handle a thrown failure.

<Callout type="warning">
  Workflow variables are shared across parallel instances. Concurrent assignments can overwrite each other. Keep per-item data in block outputs and aggregate the Parallel results instead of using shared variables as isolated instance state.
</Callout>

Use persistent storage for state that must survive across runs.
