### Design Decisions
- Provider capabilities own discoverable portfolio fields; output suggestions and monitor support derive from them instead of maintaining parallel provider-specific lists. The catalog describes supported fields, not a guarantee that every snapshot or position supplies every field, and it does not project or filter runtime payloads.
- Keep portfolio snapshots separate from order workflows. Existing adapters and `buildPortfolioDetail` still normalize portfolio data and listing identities; this branch removes empty order placeholders without adding compatibility payloads or backfills.
- Distinguish a missing value from an unresolved reference with the resolver's private `UNRESOLVED_REFERENCE` sentinel. Formatting belongs to the consuming context; a known block's missing output is not equivalent to an unknown or inaccessible block name.
- Preserve native data at exact-reference boundaries and apply JSON escaping only where JSON text is expected. Do not recursively reinterpret referenced payloads or guess that strings containing numbers, booleans, or JSON objects should change type.
- Provider-change condition reset belongs in the monitor draft merge, not a rendering side effect in the condition picker. OAuth configuration availability remains separate from credential/account authorization, which continues through existing trading services.

### Future Branch Guardrails
- Do not advertise unavailable portfolio valuations, substitute zeros for absent broker data, or use the capability map as proof that a field is present in a particular snapshot. Preserve optional values and canonical listing identities; Robinhood's absent valuation fields remain absent in serialized output.
- Adding an output field does not automatically add a new monitor metric. Extend `TRADING_PORTFOLIO_MONITOR_METRICS` and the evaluator deliberately when introducing a new metric, then derive provider support from the declared output fields. Keep capability availability gates and performance-window behavior aligned.
- When changing a portfolio provider, clear incompatible conditions through the draft merge; do not mutate condition state while rendering or retain unsupported metrics as selectable-looking placeholders.
- Check trading block availability with registered OAuth service IDs and operation kinds. Do not treat the availability map as proof that the user has a connected credential or authorized account; existing workspace/credential checks in `apps/tradinggoose/lib/trading/portfolio-detail.ts` still apply.
- Preserve the distinction between unresolved references and missing values. Keep numeric indexing, own-property lookup, and literal nonnumeric bracket keys consistent for start and named outputs. Do not generalize the missing-output policy to every loop/parallel failure: specialized nested current-item resolution and virtual execution checks retain their own errors.
- Keep exact native-reference payloads opaque. Do not restore recursive JSON-string coercion, string replacement-token interpretation, environment expansion inside those payloads, or implicit conversion of nested descriptor-shaped objects. For non-string Builder rows, missing/null values are omitted; native null is preserved in pass-through rows and JSON values, not universally across all row types.
- Preserve the existing response envelope, status/header handling, conditional input activation, and Human in the Loop conversion reuse. Response mode references must resolve before selecting active inputs so an inactive Builder/Editor branch is not evaluated. No legacy portfolio or response-conversion fallback is required.
