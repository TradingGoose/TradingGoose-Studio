### Design Decisions
- The scanner separates route scans from all-project scans: route mode uses *resolveRouteEntries()* plus owned namespaces for focused reporting, while all mode provides the baseline used for orphan detection.
- Hardcoded-candidate suggestions are ownership-aware. *ownership.ts* and *deriveComponentKeySegment()* keep fallback keys aligned with route namespaces instead of generating flat global names.
- Repo-boundary checks now reuse *isPathInsideDirectory()* across entry discovery and graph materialization instead of relying on raw string-prefix checks, which keeps containment logic consistent and closes the sibling-prefix escape hole without changing import-resolution order.
- The final implementation keeps *scan.ts* as orchestration only and moves graph, runtime, semantics, and shared descriptor logic into dedicated submodules so future scanner changes stay localized instead of growing another monolith.
- Type-checking runs *next typegen* first and uses *tsconfig.typecheck.json* so the catalog scripts and app code share one explicit typecheck surface that includes *.next/types*. The real-app inventory guardrails now share a lazy fixture so one dashboard/all-mode scan pair backs both heavy assertions.
