### Design Decisions

- Better Auth owns account/session mutations, OTP and reset-token redemption, OAuth linking and native Stripe subscription persistence. Studio's hooks keep login allowlists, registration eligibility and organization/billing policy at those boundaries. `authTransaction` in `apps/tradinggoose/lib/auth.ts` shares the Drizzle transaction connection with registration and initial-organization reads, rather than opening unrelated reads while a native auth transaction holds a connection.
- User ID remains the durable account identity. Native usernames are normalized for uniqueness while `displayUsername` preserves chosen casing; social accounts are not assigned generated usernames. `getRegistrationDenialReason(email, store)` returns a denial string or `null`, replacing a parallel eligibility DTO and supporting the active transaction store.
- SSO provider suggestions are not a trust list. Verified domains, native first-link checks and existing organization membership govern sign-in; Studio's organization invitation routes retain membership and seat ownership. OIDC callbacks remain `/api/auth/sso/callback/<providerId>` and SAML callbacks remain `/api/auth/sso/saml2/sp/acs/<providerId>`, separate from the generic OAuth cutover below.
- Native checkout composes plan/interval line items instead of Studio replacing them with a custom monthly-price array. Existing subscription-upgrade authorization and seat normalization remain in `apps/tradinggoose/app/api/auth/[...all]/route.ts`; this final comparison does not add a separate seat-quote workflow.
- Apply the committed generated migration before running the upgraded auth/Stripe code. Complete SSO TXT verification before relying on domain-based sign-in. Preserve committed/applied migrations and their snapshots; callback-registration rollback uses the provider-side values described below.

**Accepted for this release.** Studio uses Better Auth’s native single-use password-reset links. A link issued before an email change can still reset the same account until its original one-hour expiry. New reset requests for that account use its current address. [Better Auth 1.7.26 reset implementation](https://github.com/better-auth/better-auth/blob/v1.7.26/packages/better-auth/src/api/routes/password.ts)

**Open OTP finding.** During Studio’s 15-minute code lifetime, a password-reset code can apply to a different account that acquires its address. A pending destination code can also complete after an intervening change of the account’s current email. Better Auth 1.7.26 checks the current mailbox when requesting a change and offers no setting to invalidate both kinds of code when ownership changes. [Better Auth email OTP implementation](https://github.com/better-auth/better-auth/blob/v1.7.26/packages/better-auth/src/plugins/email-otp/routes.ts)

#### OAuth callback cutover

Before deployment, check the allowed redirect URIs on each enabled integration’s existing OAuth app. Add the new URI if it is missing. Continue using the same app, client ID, and secret. Better Auth 1.7.26 sends generic OAuth integrations through its shared callback route. Built-in Google and GitHub sign-in already use that route. [Pinned Better Auth generic OAuth implementation](https://github.com/better-auth/better-auth/blob/v1.7.26/packages/better-auth/src/plugins/generic-oauth/index.ts)

For the GitHub repository integration on `www.tradinggoose.ai`, the original URI was `https://www.tradinggoose.ai/api/auth/oauth2/callback/github-repo`. The new URI is `https://www.tradinggoose.ai/api/auth/callback/github-repo`. GitHub sign-in uses `/api/auth/callback/github` in both versions.
