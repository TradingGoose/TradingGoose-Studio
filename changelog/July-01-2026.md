### Design Decisions
- Entity-list sessions are live read-only projections, not editable documents. Clients subscribe to `members`, while create/update/delete code paths mutate canonical DB rows or saved entity Yjs docs and then call `refreshEntityListSession()`.
- Saved entity editor docs remain separate from list projections. Editors open `useSavedEntityYjsSession(entityKind, entityId, workspaceId)` for field edits and save through `saveSavedEntityYjsDocToDb()` or `applySavedEntityState()`, while lists only carry discovery metadata.
- Realtime failures are intentional user-facing failures in Studio editing contexts. `SavedEntityRealtimeRequiredError` and `WorkflowRealtimeRequiredError` prevent stale DB fallbacks from overwriting collaborative state.
- Deployed execution is explicitly different from Studio editing. `readSavedEntityFieldsForExecution()` and `readSavedEntityListFieldsForExecution()` use `isDeployedContext` to choose DB-backed rows for deployed runs and Yjs-backed snapshots for non-deployed runs.
- Widget selection is local and validated. List widgets no longer auto-select the first entity by store side effect, and editor widgets only open requested/default IDs that exist in the current `useEntityList()` membership.
- MCP server state no longer needs a dedicated Zustand store. The list projection plus `useMcpTools()` cache/event behavior now owns the UI data flow for server membership and discovered tools.
- Public workflow marketplace publishing was removed rather than shimmed. The branch follows the project no-legacy rule by deleting the route, schema exports, SDK status field, and stale copy instead of keeping compatibility surfaces.
- Agent tool hydration is strict: an agent block runs with exactly the tools selected on it (minus explicit `usageControl: 'none'`) or fails with the reason. Hydration never silently drops a tool — a dead MCP server, a tool missing from a server, or an unresolvable selection fails the block honestly instead of running a silently shrunk toolset. Per-call failures during the run still reach the model as tool errors, which is where graceful degradation belongs.

### Future Branch Guardrails
- Do not add new widget-local stores for entity membership. Workflow, MCP server, skill, custom tool, indicator, and knowledge-base lists should consume `useEntityList()` and let server mutation paths refresh the list session.
- Do not write to entity-list `members` from client UI code. List membership changes should flow through canonical create/update/delete operations, `applySavedEntityState()`, `refreshWorkflowList*()`, or `refreshEntityListSession()`.
- Do not add DB fallback reads for Studio editing state. If Yjs bridge/snapshot access fails in non-deployed context, surface the realtime-required error instead of reading stale rows.
- Do not skip `isDeployedContext` when adding execution paths. Deployed workflows should read DB-backed saved entity state; Studio/runtime editing should use Yjs-backed state.
- Do not reintroduce `stores/mcp-servers/*`, `/api/mcp/servers/[id]`, public workflow marketplace routes, `WorkflowStatus.isPublished`, or marketplace schema exports.
- Do not add catches that silently drop agent tools or convert saved-entity execution-read failures into null/"not found". Hydration and execution reads fail with the real error (`SavedEntityRealtimeRequiredError` 503 vs 404 bootstrap errors); only genuine 404s may narrow to an absent-entity state where absence is legitimate.
- Keep entity-list members as discovery metadata. Add detail fields to saved entity docs and detail readers, not to every list result, unless the field is needed for selection/search/list display across widgets.
- When adding list-widget create flows, generate default names through `generateAvailableName()` against current `members.map((member) => member.entityName)` instead of duplicating collision logic.
- Keep workflow folder metadata refreshes tied to `refreshWorkflowList()` after folder delete/promote or workflow metadata updates so folder trees stay aligned with the list projection.
