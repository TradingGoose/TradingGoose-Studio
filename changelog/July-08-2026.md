### Design Decisions
- Dashboard layouts stay owner-scoped even when they are modeled as saved entities: the user-specific owner key is required by `apps/tradinggoose/lib/dashboard-layouts/operations.ts`, `apps/tradinggoose/lib/copilot/tools/server/entities/dashboard-layout.ts`, and the Yjs/copilot transport layer. Shared workspace access gates the feature, but persistence ownership remains per member.
- Watchlists intentionally move the other direction: root watchlists are shared workspace documents with `userId = null` and `parentId = null`, and watchlist items are workspace-owned children. `apps/tradinggoose/lib/watchlists/document.ts` only reads and writes that shared-root shape.
- Widget behavior is deliberately normalized behind contract objects rather than scattered utility functions. Effective params, linked reference fields, catalog metadata, and copilot-edit semantics now come from the same per-widget contracts that renderers consume.
- Entity-list Yjs sessions are treated as disposable projections. `apps/tradinggoose/lib/yjs/server/snapshot-bridge.ts` refreshes them from canonical DB state and deletes the session on refresh failure instead of treating the projection as primary state.
- `packages/db/migrations/0038_bizarre_nova.sql` is not an in-place migration for populated staging watchlist data. This branch intentionally avoids backfill logic, compatibility reads, or mixed ownership fallbacks. Rollout requires reset/reseed of legacy watchlist data.

### Shared Contracts and Helpers to Reuse
- Reuse `apps/tradinggoose/lib/dashboard-layouts/operations.ts` and `apps/tradinggoose/lib/dashboard-layouts/read-projection.ts` for layout CRUD, provisioning, hydration, and list refresh. Future dashboard code should call these helpers instead of recreating layout-row queries or active-layout toggles.
- Reuse `apps/tradinggoose/widgets/layout-document.ts` for dashboard layout document parsing, raw-structure edits, and saved-entity serialization. The canonical formats are `DASHBOARD_LAYOUT_DOCUMENT_FORMAT` and `DASHBOARD_LAYOUT_STRUCTURE_DOCUMENT_FORMAT`.
- Reuse `apps/tradinggoose/widgets/widget-contracts.ts`, `apps/tradinggoose/widgets/widget-contract-types.ts`, and each widget's `apps/tradinggoose/widgets/widgets/*/contract.ts` file for widget metadata, param normalization, linked field ownership, and copilot catalog exposure. New widget surfaces should extend the contract layer instead of adding another helper namespace.
- Reuse `apps/tradinggoose/widgets/widget-mutations.ts` and `apps/tradinggoose/widgets/widget-config-runtime.tsx` for panel/widget mutations and pair-color propagation. Client code and copilot tools should share those mutation semantics.
- Reuse `apps/tradinggoose/lib/watchlists/document.ts` and `apps/tradinggoose/lib/watchlists/validation.ts` for watchlist document materialization, normalization, and tree validation. Do not add parallel watchlist serializers or item-level tree mutation code elsewhere.
