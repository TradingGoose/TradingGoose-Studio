# July-08-2026

## feat/copilot-tools vs staging

### Summary

- Makes workspace watchlists first-class saved entities backed by the already-applied workflow-style folder/item schema.
- Makes each user-owned widget layout one saved entity whose layout, widget, and color-pair state have independent Yjs document owners and database rows.
- Adds the complete watchlist, listing-search, layout, and widget-child Copilot tool contracts to both Studio Copilot and Copilot-MCP.
- Centralizes saved-entity identity changes while keeping names out of editable Yjs content documents.

### Canonical watchlist design

- `watchlist_table` is the folder table. A workspace-owned row with `parentId = null` is a watchlist entity; descendant folder rows are sections.
- `watchlist_item` is the item table. Each row stores the canonical structured listing identity and points to its watchlist and containing folder.
- `apps/tradinggoose/lib/watchlists/document.ts` is the only row/document materializer. It composes and persists whole watchlist documents through those two tables.
- Watchlist Yjs content contains only `settings` and UUID-keyed item maps; moves and listing edits mutate the same item owner, while deterministic read projection resolves concurrent semantic duplicates before persistence. The root row/list session owns the watchlist name.
- The Copilot entity surface is `list_watchlist`, `read_watchlist`, `create_watchlist`, `edit_watchlist`, and `rename_watchlist`.
- `search_listing` is a workspace-agnostic discovery tool that returns canonical listing identity objects for watchlists and other listing consumers.
- Watchlist review UI renders section/listing changes as resolved ticker-style rows rather than exposing raw identity JSON.

### Canonical layout and widget design

- A widget layout is one owner-scoped `dashboard_layout` saved entity. Widgets and color pairs are internal child document owners within that entity; they are not standalone workspace entities and never enter entity lists or generic entity tools.
- The hierarchy has four independent Yjs boundaries:
  - the layout document stores topology, panel ids, widget `identityId`, and `widgetKey`, persisted only to `layout_maps.layout`;
  - each widget document stores one identity's local `pairColor` and `params`, persisted only to its `layout_widgets` row;
  - each non-gray color-pair document stores one layout/color shared context, persisted only to its `layout_pairs` row;
  - an entity referenced by effective widget params connects to its existing entity Yjs document.
- `apps/tradinggoose/widgets/widget-config-runtime.tsx` mounts the widget document for one panel and the selected pair document independently. It composes `layout.widgetKey`, widget-local state, and pair-shared state only as an ephemeral render config; no provider mutates, reconnects, seeds, or repairs another provider.
- Entity editors inside widgets continue to subscribe to their own saved-entity Yjs documents.
- Dashboard bootstrap passes topology only. Each panel opens its widget document, then its selected pair document, without copying child state through page props or aggregate React state.
- Landing dashboard/widget previews use the same topology helpers and local Yjs runtime instead of parallel layout or widget mutation implementations.
- The layout Copilot surface is `list_layout`, `read_layout`, `create_layout`, `edit_layout`, and `rename_layout`.
- The widget-child Copilot surface is `get_available_widgets`, `get_widgets_metadata`, and `edit_widget`.
- One serialized layout-structure mutation owner handles resize, split, close, and widget replacement, committing topology and widget-row lifecycle together. `edit_widget` edits only an existing widget's params, pair color, and shared color-pair fields.
- Empty panels continue to render the canonical empty-widget fallback and selector; selection delegates to the layout-owned replacement action.
- Layout reviews render topology with widget keys. Widget reviews use the entity-document JSON diff viewer.
- `read_layout`, `edit_layout`, and `edit_widget` return the same complete read-time `{ layout, widgets, colorPairs }` projection plus `effectiveLayout`. That projection is an inspection result assembled from independent owners, never a persisted or connected aggregate document.

### Ownership and permissions

- Layout rows are scoped by `(workspaceId, userId)`. Every workspace member with read access can create, activate, reorder, rename, delete, and edit personal layouts and widget parameters.
- Workspace `write` permission still governs shared workspace entities such as workflows, knowledge bases, custom tools, skills, MCP servers, watchlists, and indicators.
- A default personal layout is provisioned transactionally on workspace creation and when access is granted. The dashboard entry path also ensures provisioning for an existing member.
- Workspace-level default workflow/watchlist/tool/skill/indicator/MCP seeding was removed. Creation belongs to each entity's explicit create flow.

### Identity and realtime contracts

- `apps/tradinggoose/lib/saved-entities/identity.ts` is the canonical identity writer for workflow, knowledge base, custom tool, skill, MCP server, watchlist, indicator, and dashboard layout names.
- Content saves update only editable document fields. Rename tools and dashboard rename actions delegate to the same identity command, return its exact persisted timestamp, and refresh the matching entity-list Yjs projection.
- Copilot layout/widget mutations stage owner-specific semantic state through the socket-server bridge, so open dashboards receive server-side edits without merging independent document histories.
- Entity-list Yjs sessions remain disposable DB-backed projections; DB rows own identities and list metadata.

### Removed or replaced paths

- Removed the old dashboard layout REST write handlers, dashboard pair store, aggregate root widget runtime, optional no-provider mutation hook, duplicate `LayoutNode` mutation helpers, and widget-side topology writers.
- Removed the `list_widgets` compatibility name. `get_available_widgets` is the only catalog contract.
- Removed old per-item watchlist mutation/export routes and mixed user-owned root handling. Whole-document operations are the only watchlist entity write path.
- Removed generic socket/API name mutation paths and entity-document name aliases. Identity changes use the central saved-entity command.
- Removed last-entity delete guards and global default-entity seeding. These were cross-boundary policy layers rather than requirements of the canonical entity contracts.
- Removed layout-driven workflow reader/session/editor branches. Workflow keeps its existing Yjs contract; only direct watchlist/listing consumers and the widget registration shell changed.
