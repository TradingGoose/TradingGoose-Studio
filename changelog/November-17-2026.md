### Design Decisions

- Better Auth owns session synchronization and native auth endpoints. Profile mutations use `client.updateUser`, and one UI-local pending patch bridges successful saves until their individual fields are acknowledged; an unrelated or stale session response cannot discard an unacknowledged field. No second persistent profile/session store is introduced.
- Email changes require both mailboxes even when signup verification is disabled. Signup verification uses `verifyEmail` rather than passwordless sign-in: the latter retains native credential revocation for unverified accounts. Login allowlists apply before verification creates a session and against the stored email before username login creates one.
- Proof ownership is encoded at issuance and carried through redemption, rather than repaired by deleting old verification rows after an email change. JSON tuples avoid address-pair collisions, and strict reset records reject unbound formats. The version-pinned patch stays scoped to native dependency routes/utilities; `patches/README.md` records its upstream references and upgrade removal criteria.
- Native SSO discovery, domain proof and account matching replace manual endpoint construction and name-based trust. Disabling native organization provisioning preserves Studio's application-owned invitation, role and seat authorization boundaries.
- Seat quotes use the same server aggregate occupancy as invitation/upgrade validation. Licensed starting seats come from the selected organization's billing data; roster lengths and another organization's cached data cannot authorize a quote. The browser seat dialog supplements the existing server checks.
