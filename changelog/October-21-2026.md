### Design Decisions

- The block registry owns editable configuration and output metadata for containers as it does for ordinary blocks. Geometry remains structural, and execution records are derived projections rather than separately writable configuration sources.
- Configuration-only Copilot edits reuse the existing strict argument schema, canonical ID checks, validation, preview, and permission-aware apply flow. Switching modes preserves unpatched inactive values instead of resetting another mode's settings.
- Independent field values must not contend with a whole-block structural write. Text uses collaborative character edits; numbers and mixed-widget fields use atomic replacement so concurrent numeric edits cannot concatenate digits or change storage type when the editor layout changes.
- Shared text identity is part of the editor contract. Snapshot replacement, populated dynamic fields, renames, and remounts should update the existing text object; equal writes should not create Yjs updates or undo noise.
- Iteration context and completed block outputs are different contracts. Reserved context references are mode/scoping dependent; named outputs come from registry metadata. Collection evaluation belongs to container handlers, not duplicate resolver fallbacks.
- Container completion runs through normal executor logging/events. Aggregate delivery must not overwrite an applicable explicit Response block's HTTP data, status, or headers, including debug stepping and checkpoint resume.

### Future Branch Guardrails

- Patch canonical `subBlocks` IDs only. Do not add top-level container-specific Copilot arguments, restore configuration in `block.data`, or maintain writable Yjs `loops`/`parallels` maps. Structural container nodes and their edges must exist as actual blocks, not only as execution-map entries.
- Preserve active-variant validation and defaults. Do not reject valid inactive provider/mode values or supported reference templates while editing an unrelated block; do not relax literal-only container counts or coerce native boolean dropdowns into invalid numeric values.
- Persist/read live values through the shared field and snapshot APIs. Do not serialize stale structural sub-block copies, replace populated `Y.Text` objects during initialization, or choose a field's storage type from only its currently rendered widget.
- Preserve per-block field-map initialization, deletion/clear cleanup, origin-aware undo, deep-equality no-op writes, and targeted subscriptions. Independent field edits and unrelated graph updates must converge without overwriting one another.
- Keep text binding writes and fallback editor persistence mutually exclusive. Object/null values must remain intact on mount and become text only when an edit requires it; read-only or externally controlled previews must not write to the workflow.
- Keep `<loop.index>` zero-based and scoped to the active iteration; expose item references only for collection modes. Do not suggest completed container results as if they were inside-body context or restore resolver-side collection evaluation.
- Preserve the documented runtime distinctions: For/For Each completion includes ordered `results`, While/Do While completion does not, and condition-driven loops rely on termination conditions and execution limits rather than a fixed count. The Parallel Count limit of 20 does not cap collection mode, and parallel child writes still share workflow variables.
- Preserve completed-container events and newest-log selection while keeping final Response selection based on actual block type and execution order. Do not infer HTTP response behavior from an arbitrary output object's shape or asynchronous completion timing.
- Keep this a clean contract change: do not add old field-key readers, old checkpoint-shape adapters, `block.data` configuration backfills, or duplicate container registries. Keep `parallel` and `parallel_ai` distinct.
