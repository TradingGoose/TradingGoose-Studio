### Design Decisions
- Base UI is adopted through the repository's local primitive implementations rather than retaining Radix compatibility wrappers. The changed `apps/tradinggoose/components/ui/index.ts` intentionally exposes only the supported local surface.
- Base UI trigger composition is explicit: migrated controls receive their rendered element through `render`, preserving the child element rather than introducing another `asChild` adapter.
- Global providers and feedback surfaces live in `app/layout.tsx`, leaving the locale layout responsible only for locale validation and request configuration.
- Environment request construction and authentication handling live in one client module, while route handlers retain ownership of validation, encryption, permissions, and persistence conflict responses.
- Document-level tag display, definition editing, and value persistence are consolidated under `KnowledgeTags`; there is no parallel tag-editor path to keep in sync.

### Shared Contracts and Helpers to Reuse
- Import common controls from `@/components/ui` or their canonical `apps/tradinggoose/components/ui/*` module. Reuse the updated `Button`, `Dialog`, `AlertDialog`, `DropdownMenu`, `Popover`, `Select`, and `Tooltip` wrappers instead of importing the removed Radix packages.
- Use `DropdownMenuContent` for positioned menu content, `dropdownMenuItemClassName` for consistent selectable rows, and `selectTriggerClassName()` when a custom select trigger needs the standard geometry. Use `PopoverEnvironmentProvider` or the `PopoverContent` `container`, `scale`, and `zIndex` options for overlay contexts such as the workflow editor.
- Use `apps/tradinggoose/lib/environment/api.ts` for personal or workspace environment requests. Pass its `EnvironmentTarget` with the callback pathname so the shared auth handling and endpoint selection remain consistent; `apps/tradinggoose/hooks/queries/environment.ts` owns the related React Query keys.
- Use `KnowledgeTags` from `apps/tradinggoose/app/workspace/[workspaceId]/knowledge/components` with `knowledgeBaseId` and `documentId`. It owns tag-definition settlement through the existing tag hooks and synchronizes document values through `useKnowledgeStore`.
- Reuse `getWebhookRevision`, `getWebhookSnapshotRevision`, `toPublicAirtableWebhook`, and the other provider/revision helpers in `apps/tradinggoose/lib/webhooks/webhook-helpers.ts` rather than duplicating provider identity or revision logic in routes and editors.
