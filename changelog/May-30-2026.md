### Design Decisions
- Locale-aware navigation is centralized around canonical internal paths. `apps/tradinggoose/i18n/navigation.ts` explicitly documents that callers should pass paths like `/verify` and let the router apply locale prefixes, rather than pre-localizing hrefs before routing.
- Public pages use scoped message providers to avoid loading the full workspace namespace by default, but branch-specific providers such as `apps/tradinggoose/app/intl-provider.tsx` and `apps/tradinggoose/app/(landing)/components/feature/components/market-preview/landing-market-preview-provider.tsx` can merge in the exact extra message slices required by shared widgets.
- Copy ownership moved out of component-local constants and into generated catalogs plus typed access helpers so landing/auth/admin/chat/widget code can share one translation source of truth and one test surface.
- Redirect normalization in `apps/tradinggoose/i18n/utils.ts` and `apps/tradinggoose/app/(auth)/verify/use-verification.ts` intentionally treats browser redirect URLs differently from internal router paths so localized invite/auth flows stay safe and do not double-prefix locale segments.

- Reuse `apps/tradinggoose/i18n/public-copy.ts`, `apps/tradinggoose/i18n/client-messages.ts`, and `apps/tradinggoose/i18n/message-types.ts` for typed message access. New public/admin/chat/workspace code should read copy through these helpers instead of importing raw message JSON or inlining strings.

- Reuse `apps/tradinggoose/app/(landing)/components/feature/components/market-preview/landing-market-preview-provider.tsx` when a landing preview needs a narrow workspace widget message slice under a scoped provider.
- Reuse workflow/editor localization helpers from `apps/tradinggoose/i18n/block-editor.ts`, `apps/tradinggoose/i18n/workflow-inspector-core.ts`, and `apps/tradinggoose/widgets/widgets/data_chart/copy.ts` instead of adding component-local translation tables.
