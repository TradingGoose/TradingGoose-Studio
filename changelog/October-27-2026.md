### Design Decisions
- Series normalization owns daily-change semantics across providers. A separate provider quote endpoint must not bypass regular-session, adjustment, timezone, or previous-close rules; Robinhood now uses its existing historical-series adapter through the common builder.
- Price availability and error state are independent. Preserve usable prices and explicit errors together, but leave unavailable baselines/change values null instead of inventing zero or using the current daily candle as its own baseline.
- Candle coverage and trade instants have different freshness semantics. Keep coverage metadata in the shared snapshot contract so a delayed REST response cannot roll back newer trades and an old trade cannot overwrite a completed candle. Known sessions constrain quote updates; absent session metadata is not a guarantee of regular-session filtering.
- Separate per-symbol refresh scheduling from provider-wide HTTP launch pacing. Poll cadence determines when work is due; the process-local provider/API-key queue determines when requests actually start. This is not distributed quota coordination or a guarantee that every row completes within one refresh interval.
- Keep row identity, subscription correlation, and configuration scope explicit. Repeated listings may have separate row subscriptions while the server shares upstream work; credentials and provider changes must not leak old widget data into a new scope.
- Capability metadata and the planner own interval/normalization policy. Provider adapters translate canonical requests and actual upstream timestamp formats; timezone identity comes from Market and historical offsets from the timestamp's named zone, not a provider-wide fixed offset.

### Future Branch Guardrails
- Keep previous close strictly earlier than the chosen quote date and completed prices on a consistent adjustment basis. Preserve daily-only mutual-fund behavior, seven-day FX intraday lookback, and explicit intraday/premium-access errors when using a daily fallback. Do not imply every provider supports split-adjusted data.
- Preserve nulls and zero independently. An error does not invalidate every numeric value, but consumers must not reconstruct missing change from potentially incompatible inputs. `volumeUsd` currently means `volume * lastPrice`; it is not an FX-converted USD valuation.
- Preserve exclusive candle/session end boundaries, request-start coverage limits, and corrected-close handling. New-session or UTC-day trades must not inherit stale baseline/volume data. Guard every asynchronous snapshot/session lookup against removed streams, replaced subscribers, and newer results.
- Do not restart populated rows on reorder, accept packets by listing alone, reuse client IDs across invalidated scopes, or add a UI timeout that treats budget-queued rows as failed. Keep missing-configuration checks and existing server workspace/OAuth authorization separate; configured widgets must not supply another widget's credentials implicitly.
- Keep all applicable requests for a provider/API key on the shared launch gate, including pagination and latest/trade lookups. Timeout starts at fetch launch, not while waiting in the queue. Preserve caller cancellation, queue recovery, and idle cleanup; do not describe this process-local mechanism as a cross-process rate limit.
- Keep canonical intervals at the planner/adapter boundary. Normalization support must agree across block options, chart controls, tools, and adapters; do not silently accept Yahoo/Finnhub native aliases or substitute raw prices for requested adjusted data.
- Preserve canonical Market response shapes and distinguish unavailable calendars from successful empty calendars. Do not reintroduce timezone guesses, speculative response parsing, provider-specific quote methods, or compatibility/backfill paths.
